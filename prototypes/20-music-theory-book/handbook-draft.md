# 加题手册

这份手册讲怎么做一本新书：写书、题目、流程、主题和组件时按什么做，什么时候复用、什么时候新建，以及开发者用 `/change` 和 `/issue next` 加书时，代理按什么步骤做、在哪里停下来和开发者确认。文件的格式和引擎的规则见架构文档的「讲题和练习的内容」和决策 0047，这里不重复。

做书时学到对以后的书都成立的东西，整份重写进这份手册；某一本书自己的情况写在那本书的 issue 和文件里。最后几张表登记的是现有的东西，随做随更新。

## 东西和形式

| 东西 | 形式 | 谁写 |
| --- | --- | --- |
| 书、题目、流程、主题 | 声明式的文件（YAML，加录音和图片），放在对象存储里 | 加书、加题时写 |
| 组件、接口、引擎、文件的格式 | 代码，放在代码库里 | 要新的能力时才写 |

一道新题只加文件；一个新流程只加流程文件；换一套配色只加主题文件。都不改代码。引擎里不写任何一个流程、题目或组件的名字和规矩；流程要的行为引擎没有时，加一个对任何流程都说得通的词汇，写进架构文档和内容检查。不为了让流程少写几行，把某个组件的命令做成引擎的简写：每句台词都完整地写成一条调用。

## 写一本书

`book.yaml` 只写书名、年级和 `units`：按书里的顺序，每个单元一道讲题和几道练习，都写题目名。题目放在这本书自己的 `items/` 下。只为了试一个流程而写的示例题不是给孩子的题，不属于任何一本书，也不放进对象存储；它只留在这个 issue 的草稿分支上，原型里从抽屉打开。

## 写一道题

1. 选流程：按想题的思路选，不按题目的样子选。
2. 写 `item.yaml`：`workflow`、`theme`、`components`（流程里每个没有默认组件、这道题用得到的占位选哪个组件）、`params`（按流程的形参填）。标题是几个字的题名；题干、台词、答案、结论都是参数。英文只用原卷上有的。
3. 录音和图片放在题目文件夹里自己起名的子文件夹，由参数引用。录音用录旁白的命令按台词的路径生成，台词没改的不重录。
4. 跑内容检查；在手机竖屏、手机横屏、平板、笔记本、宽屏下各走一遍。

## 写一个流程

按顺序写 `summary`、`params`、`controls`、`screens`、`layouts`、`scenes`、`sequence`。

- **形参**：写出用这个流程的题要传什么，每个参数写类型和说明；某种情况才必填的写 `required: { $字段: [值] }`。流程自己的概念（比如一道题分成几部分、每部分是哪一种）就是它自己的形参，不是引擎的概念。
- **占位**：只按接口写要什么；每道题都一样的控件（关闭、换题、分段切换、标题、上一幕、字幕、下一幕、重播）给默认组件。输入从参数来；输入全是引用而在某一幕都取不到值时，这个占位在那一幕不上台。
- **排法**：先定屏幕条件（宽屏、横放的手机、竖放的平板、兜底），再按每种屏幕划区域。主角的区域用 `fit: contain`，给放大和缩小的界限；配角的区域给固定的大小或 `maxHeight`；控件的区域用组件自己的大小。会离开这道题的控件（换题、关闭）放在一起。网格的行列里带逗号的值要加引号。
- **幕**：每一幕写排法和每个区域放什么、哪个占位开始时是什么状态；作答的幕写 `forward: done`。换幕时谁该飞到哪里（比如做完的工具缩进结论板），写在这一幕的 `exit` 或某一步的 `exit` 上。
- **顺序**：`sequence` 写幕的先后，对列表参数重复的用 `for`，按参数取舍的用 `when`，给分段切换的分段写 `segment`。
- **试**：拿这类题的其他卷子写成题目文件试一遍，不改流程也写得出来才算通用。

## 写一个组件

- **一个组件一个文件夹，自己带齐一切。** 文件夹用组件的名字，里面是它的代码、样式、能力接口、演示页、它自己的素材（比如钢琴的采样、字幕的老师头像），和清单 `component.json`：
  - `needs`：它要用的别的组件；
  - `scripts`、`styles`：按顺序加载的文件，外面的库和字体写完整的网址。

  引擎按组件名读清单，先加载它要的组件，每个文件只加载一次。所以把一个组件的文件夹复制到另一套系统里，只要它 `needs` 里的组件也在，就能直接用。组件之间只通过 `needs` 依赖，再就是引擎本身（注册表、主题常量）；没有不属于任何组件的公共文件夹。
- **不画东西的也是组件。** 声音（`sound`：音效和手机上能出声的音频输出）、乐器（`piano`）这类东西，谁要发声谁就在 `needs` 里写上它。几个组件共用的外观也做成一个组件（比如 `stage-glass`），不放进别的组件或引擎里。
- **只管功能**：形状、大小、行为和接口。颜色全部用主题常量 `var(--th-名字)`，带透明度的写 `color-mix(in srgb, var(--th-名字) N%, transparent)`，两个常量之间的颜色用两个常量调出来；不写死任何颜色，也不往数据地址的图里写颜色（要上色的纹理做成遮罩，颜色用主题常量）。主题里没有的颜色就用已有的常量调，不为一个组件给主题加常量。
- **登记**：名字、实现的接口、能不能随宽度自己排（`fluid`）、开讲前要预先加载什么（`preload`）。不能随宽度排的，宽度变了引擎会重画它再摆回状态。
- **实现接口**：命令、事件、`getState`、`setState`、`stop`。被别的东西飞向其中一项的，实现 `positions.rect`。
- **弹出来的东西**（下拉列表、提示）放在浏览器的顶层（popover），盖在页面所有东西上面，不被别的区域挡住，也不被裁掉。
- **放不下时怎么办由组件自己定**（上下转、左右转、两个方向都转、淡出或变小），可以用引擎的公共转盘。
- **样式只在本组件里生效**：类名和动画名带自己的前缀；组件里的方法名不和接口的命令同名。
- 先做组件的演示页给开发者确认（见下面「原型」）。

## 写一个主题

主题文件给出代码库里规定的每一个常量的值，只有颜色等不改变大小和行为的东西。新主题先做原型，在几个组件和整个舞台上给开发者看。

## 复用还是新建

- **组件**：现有组件的接口够用就直接用；要的是同一样东西的新能力就扩展；要画的是一样新东西，或者扩展会让它管别人的事，就新建。判断时问：画的是不是同一样东西？要不要知道别的组件？加进去以后接口还能不能几句话说清楚？几个组件都要的东西，做成一个它们都 `needs` 的组件。
- **接口**：几个组件做同一类事就用同一个接口；流程要一类新的事，先定成一个新接口。
- **流程**：同一种想题的思路用同一个流程，只换参数；这类题多一种问法，加形参和幕；思路、作答或判分方式不同就新建。
- **组件和引擎的分界**：画在画面上的东西、发出的声音都是组件；读文件、检查、加载、排版、动作、按流程走是引擎的。

## 做一本新书

开发者把材料放在本机，分两步说。

**第一步 `/change`**

```text
/change 做一本新书
材料：<文件路径，一行一个>
要求：<一句话，比如“每个考点一道讲题，后面 3 道练习”>
```

代理读材料，按考点和想题的思路分类，对照下面几张表列出要复用、扩展和新建的东西，问清书名、年级和学科，拆成 issue 给开发者确认。

**第二步 `/issue next`**，代理在这些地方停下来确认：

1. 每个新组件、扩展、新主题、引擎的新词汇，先做原型给开发者试。
2. 流程一个一个做，每个带它的第一道真题：先讲清为什么这样归纳、要哪些参数和占位、怎么排、怎么分幕；开发者同意后用第一道真题做讲题原型，调流程和做题一起进行。开发者确认了，再做下一个流程。所有流程都做完，再补其余的题。
3. 每道题先给分镜（一幕一幕说什么、做什么、谁是主角、得出什么结论），确认后再做。
4. 学到对以后都成立的东西，马上重写这份手册。

每次给开发者看原型，先说清这次要确认的是什么：一个组件、一个流程、引擎的一部分，还是一道题；示例内容要说明不是书里的。开发者提出的改动，先判断改的是题目、流程、主题、组件还是引擎，不为一处改动加没要求的设置。开发者说某个动画“没有”时，也看开发者的系统是不是打开了“减少动态效果”。

## 原型

- **组件的演示页**（组件文件夹里的 `demo.html`）：按组件的清单加载它和它要的组件；打开时先出加载页；组件放在舞台的背景上，外面一圈能开关的虚线；一排按钮发它的命令，记录框列出它发出的事件；一张表写清输入、外观、命令、事件、接口；页面按 `content/themes/` 的主题上色。不画东西的组件，演示页是一排检查按钮和一个能复制的结果框。
- **讲题原型**：用流程的第一道真题，和产品一样全屏、不滚动，引擎读书、题目、流程和主题文件，按题目用到的组件名加载组件，照着走，旁白用真的录音。只有原型有的说明放在角上的抽屉里。

给开发者看之前自己先查：

- 在手机竖屏、手机横屏、平板竖屏、笔记本、宽屏下各从头走一遍：哪里都不滚动；每个组件都在自己的区域里，主角最大；结论板显示的正好是它记下的结论；换题和关闭在一起，换题的列表不被任何东西挡住；该飞的东西飞到了目标。
- 用“孩子”脚本走完整道题：答错、往回、点结论、跳过、提问前点选项都试过；作答时下一幕和后面的分段按不了，往回能按。
- 会动的东西逐帧量过，只朝落点走、不回头；能点的东西都点过一遍；每个组件的演示页打开没有报错；组件量自己的文字之前，它的字体已经加载好。

## 能力接口

| 接口 | 能做什么 |
| --- | --- |
| `point` | 亮起、聚光、贴标签、清除；报告点到哪里 |
| `count` | 一格一格地数 |
| `meter` | 放进拍号、细分 |
| `play` | 播放、停 |
| `mask` | 遮住、揭开 |
| `set` | 换成另一份内容 |
| `answer` | 让孩子作答、替孩子作答、标出对错、擦掉、锁住；报告孩子答了什么（`answer.given`） |
| `strike` | 划掉一项 |
| `positions` | 报出某一项在屏幕上的位置（`positions.rect`） |
| `conclude` | 推一条结论（可带从哪里飞来）、摆成哪几条；点一条时报告 `go.origin` |
| `narrate` | 字幕和旁白：说一句、轮到孩子、标签、暂停、语速 |
| `leave`、`questions`、`parts`、`back`、`forward`、`restart`、`title` | 每道题都有的控件：关闭、换题、分段切换、上一幕、下一幕、重播、标题 |

## 现有组件

每个组件在 `components/<名字>/`，颜色都来自主题常量；“要”是它清单里的 `needs`。

| 名字 | 做什么 | 接口 | 要 |
| --- | --- | --- | --- |
| `sound` | 不画东西：按下的声音，和手机上也能出声的音频输出 | — | — |
| `piano` | 不画东西：用自己的钢琴采样弹出音高，开讲前预先加载 | — | `sound` |
| `stage-glass` | 不单独上台：控件共用的深色玻璃外观、圆形图标按钮、下拉列表、题号圈、图标 | — | `sound` |
| `close`、`scene-prev`、`scene-next`、`replay` | 圆形图标按钮：关闭、上一幕、下一幕、重播 | 各自的控件接口 | `stage-glass` |
| `question-menu` | 换题按钮和题目列表（列表在顶层） | `questions` | `stage-glass` |
| `part-switch` | 分段切换 | `parts` | `stage-glass` |
| `question-title` | 题号、标题，能展开题干 | `title` | `stage-glass` |
| `narration` | 字幕条：老师头像（自带）、台词、暂停、语速 | `narrate` | `stage-glass` |
| `score` | 谱：画、点音符发声、聚光、标记、播放（随宽度自己排） | point、play、positions | `piano`、`sound` |
| `beat-grid` | 拍尺：把一小节按时值等比例画开，按拍号分拍，数、细分 | point、count、meter、set、play | `piano`、`sound` |
| `conclusion-stack` | 结论板转盘：焦点上的最大，点一条回到得出它的那一幕（随宽度自己排） | conclude、point、mask、set、positions | `sound` |
| `choice` | 选项打勾、划掉、对错 | answer、point、strike、set、play、positions | `piano`、`sound` |
| `fill` | 句子里的格子加按键 | answer、point、set、positions | `sound` |
| `keyboard`、`scale-ladder`、`circle-of-fifths`、`fact-card`、`note-place` | 有演示页，还没接到讲题上，没有能力接口 | — | `piano` |
