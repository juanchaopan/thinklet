# 加题手册

这份手册讲怎么在好奇星球上做一本新书：书里的题目由哪些东西组成，什么时候复用、什么时候新建，以及开发者用 `/change` 和 `/issue next` 加书时，代理按什么步骤做、在哪些地方停下来和开发者确认。它适用于所有学科和年级。代理每次做加书、加题、加流程、加组件的 issue，先读完这份手册。

做书的过程中学到的东西，整体重写进这份手册，不在末尾追加；手册读起来要像一次写完的。只写对以后的书都成立的做法，某一本书、某一门课自己的情况写在那本书的 issue 和题目文件里。

## 四样东西

一道讲题或练习由四样东西组成：组件是代码，流程、题目和书是内容文件。

| 东西 | 是什么 | 放在哪里 |
| --- | --- | --- |
| 组件 | 画在画面上、能被复用的一块，比如一张谱、一个图形、一组选项、一个填空键盘 | `apps/web/src/app/shared/lesson/` 下每个组件一个文件夹；参数的格式在 `packages/contracts` |
| 流程 | 一道讲题或练习从头到尾的一串幕和步骤：每一步让哪个组件做什么、老师说哪句话、等孩子做什么、得出什么结论 | `content/workflows/<流程编号>/workflow.yaml` |
| 题目 | 绑定一个流程，填上这道题自己的素材、台词、答案和评分标准，带自己的图片和录音 | `content/books/<书本编号>/questions/<题目编号>/` |
| 书 | 书本表里的一行（书名、适用年级、教学年级、学科），加上单元的顺序 | 书本表的一行写在迁移脚本里；单元顺序是 `content/books/<书本编号>/book.yaml` |

讲题和练习就是把组件装配进来，再按流程走。

除了组件，播放器还给组件提供服务，比如发声的“音源”。服务不是画面上的东西，由播放器交给组件；组件只管用，不管它从哪来。

### 组件

**边界。**一个组件只管它自己画的那一块，包括它自己的按钮、标签、气泡和下面的名称。下面这些都不属于组件：

- 题目画面后面的背景，是播放器自己的样子；
- 几个组件怎么排（一行几个，还是上下排），由流程决定；
- 老师的旁白和字幕，是另一个组件；
- 作答框里填什么，由作答组件管。

**接口。**组件只通过三样东西和外面打交道，不直接调用别的组件：

- **输入**：题目文件给的内容，以及模式（讲题或练习）、大小这类设置。
- **指令**：流程让它做的事，比如“聚光这一部分”“在这几处贴 A、B、C”“一个一个数”“播放”“清除”。
- **事件**：它告诉外面发生了什么，比如“孩子点了第 5 个，是什么”。流程只靠事件往下走。

两个组件要联动（比如点了一个，另一个也亮），由流程收到前一个的事件后给后一个发指令；组件之间互不知道。组件要用的服务从外面交给它，组件不知道服务背后是什么。

同一份素材可以交给几个组件，各取所需。比如同一段谱，一个组件画成谱，另一个组件按时值画成比例图；素材只写一次，写法相同。

**外观由组件自己定。**颜色、材质、光、字体都写在组件里面，不从外面继承，放在什么画面上都是同一个样子。流程、题目和播放器都没有主题或配色这类字段；开发者没要求的设置不要加。

**画面质感。**组件要有电影级别的质感，不是平面的黑白图：

- 有材质：比如纸有纹理、厚度和阴影，木头有纹路，琴键有象牙和乌木的光泽。
- 有光：标亮的东西发出柔光；聚光时其余部分变暗，光落在要看的地方。
- 有动作：按下、出现、标亮、贴标签都有短而柔的动画，减速停到位；系统打开“减少动态效果”时动画在 100ms 内完成。
- 学科的专用符号（音符、化学结构、几何记号等）用现成的库画出的字形，不自己描，这样每个组件里的同一个符号一模一样，也像正式的印刷品。

**错和对用颜色以外的方式也能看出来。**组件要表现“多了”“缺了”“不对”时，除了换颜色，还要有形状上的区别，比如虚线框、断开的线、问号。

**讲题和练习两种模式。**讲题里可以有操作，但不记录结果；练习里组件只管作答或只显示流程标好的东西，不给提示。本身就是提示的组件（比如把答案的推理过程画出来的图），练习里一般不出现。声音也按模式分：讲题里能播放、点了会发声；练习里组件不发声，只有播放器在提交、答对、答错时发提示音。

**操作。**

- 手指、鼠标、键盘都能用。
- 点不准也要点得中：可点的东西尽量不小于 44×44 像素；画面上很小的东西（比如谱上的一个音符）按离手指最近的算；连成一片的东西（比如一条时间轴上的各段）点到哪段就是哪段，超出一定距离才算点空白。
- 点了以后的高亮和说明两秒后自己淡掉，点空白处马上清掉；流程要求一直亮着的才一直亮着。
- 只用键盘时有清楚的焦点样式，方向键在可点的东西之间移动；用手指和鼠标点的时候不出现焦点框。

**声音。**组件只说“弹哪个音、多长”，交给播放器给的音源。手机只在孩子的操作里才能开始出声，有的手机在静音键打开或页面没播过媒体时一直不出声；这些限制由播放器统一处理，组件不管。

**文字。**组件画出来的术语和记号用这门课考试的原文；中文只出现在旁白和字幕里。文字不压在图上：要指某几处时，用 (a)(b)(c) 或 A、B、C 这样的标记，名称写在图的外面，像考卷一样。

**屏幕大小。**手机、平板、电脑都要好用：

- 宽屏上画大一些，组件占满流程给它的宽度。
- 窄屏上先换行，不缩小；按自然的单位换行（比如谱按小节，键盘按八度，时间轴按拍）。
- 一个单位本身都放不下时，才整体缩小到刚好放下。
- 窄屏上可以用考卷上的缩写（比如第一行写全称，后面写缩写）。
- 一组同样的组件排在一起时，大小一样、对得齐；表示同一种量的（比如时间、长度），同样多的量占同样宽，孩子可以一格对一格地比。
- 整个页面不能左右滚动。

**加一个组件要交的东西。**

1. 组件的文件夹和代码，在组件对照表里登记编号。
2. `packages/contracts` 里它参数的 schema。
3. 组件测试：每个状态跑 axe，三种屏幕各截一张图。
4. 在这份手册的“现有组件”一节里加一行。

### 流程

流程的文件格式在流程设计确定后写进这一节。现在已经定的：

- 讲题流程和练习流程分开，同一个题型的讲题和练习用不同的流程。
- 每个流程带一个教学年级的范围，只作参考；出题时尽量选范围覆盖这本书教学年级的流程，没有合适的就新建。
- 流程决定用哪些组件、怎么排、每一步给哪个组件发什么指令、等哪个事件。
- 练习流程写这类题默认的判分方式：整题对错、按小题算百分比，或者按步骤。

### 题目

题目的文件格式在流程设计确定后写进这一节。现在已经定的：

- 一道题绑定一个流程，选若干组件。
- 素材用组件认得的格式写（比如谱用 ABC 记谱法）。
- 旁白台词写在题目文件里，用 `task narrate` 录成 MP3，放在题目的 `narration/` 里，和题目一起提交。
- 答案和评分标准写在题目文件里：每个作答点的答案（可以有几种都算对），每个作答点几分；和流程默认不同的判分方式也写在这里。
- 自己的图片只用 WebP 或 PNG；动画由组件做，题目里只写动哪个、怎么动。
- 原题不照搬：由真题改编，答案人工核对。

### 书

- 书本表的一行写在一个新的迁移脚本里：编号、书名、简介、适用年级的范围、教学年级、学科。新学科也在迁移脚本里加。
- `book.yaml` 写单元的顺序，每个单元一道讲题加几道练习。
- 封面放在 `content/books/<书本编号>/cover.webp` 或 `cover.png`。

## 复用还是新建

先找现有的组件和流程，能用就用；不能用时按下面的顺序考虑。

**组件**

1. **直接复用**：现有组件的输入和指令已经够用。比如一题要四个小图，就是同一个组件放四个，排法交给流程。
2. **扩展**：要的是同一样东西的新能力，而且这个能力只和它自己有关。比如让谱上的装饰记号按实际弹法发声，加在乐谱里；新的能力要在讲题和练习两种模式下都想清楚。
3. **新建**：要画的是一样新东西，或者扩展会让一个组件管别人的事。比如键盘是新组件，不塞进乐谱；按比例画时值的节拍格是新组件，不塞进乐谱，因为乐谱的排法要照印刷习惯，比例图要照时间；旁白字幕条是新组件，不塞进乐谱的播放按钮。

判断时问三个问题：它画的是不是同一样东西？它要不要知道别的组件？加进去以后，接口还能不能用几句话说清楚？

不画东西、多个组件都要用的能力（比如发声），做成播放器提供的服务，不放进某个组件。

**流程**

1. **直接复用**：同一种教法，只是换素材。
2. **新版本**：教法一样，但要给另一个教学年级范围的孩子讲（低年级动画多，高年级讲得深），就新建一个范围不同的流程。
3. **新建**：想题的思路不同，或者作答和判分的方式不同。

## 做一本新书

开发者把材料（PDF、分类文件等）放在本机，按下面两步说。两个命令都只要说这几行，其余的代理会问。

### 第一步：`/change`

```text
/change 做一本新书
材料：<文件路径，一行一个>
要求：<一句话，比如“每个考点一道讲题，后面 3 道练习”>
```

代理这样做：

1. 读材料。有分类文件就直接用分类文件，只在核对细节时看原文。
2. 把题目按考点和作答形式分好类，列出这本书要哪些考点、每个考点几道讲题和练习。
3. 对照“现有组件”和“现有流程”，列出要复用、扩展和新建的组件和流程。
4. 问开发者书的信息：书名、适用年级、教学年级、学科。
5. 拆成 issue，写好每个 issue 的目标、范围和验收标准，给开发者确认后创建。

### 第二步：`/issue next`

```text
/issue next
材料：<和第一步一样的文件路径>
```

代理按 issue 的五个步骤做，在这些地方停下来和开发者确认：

1. **组件**：每个新组件和扩展，先做一个可以点的网页原型给开发者试，见下一节。开发者确认样子、手感和逻辑后，才做下一个。
2. **流程**：每个新流程，逐个解释为什么这样归纳、用哪些组件、一幕一幕怎么走，给开发者看原型，确认后再做下一个。
3. **书的信息和题目的信息**：书的信息在开始时问；每道题的素材、要点和答案也问开发者。
4. **每道题**：先给分镜：怎么教，一幕一幕说什么、做什么，哪些组件直接画在画面上、哪些要按按钮才弹出来。开发者确认后再做；做完开发者审过，才做下一道。
5. **手册**：学到对以后的书都成立的东西（开发者的一次纠正、一条新规矩、一个新组件或服务），马上把整份手册重写一遍并提交，不等到组件、流程或题目做完。对话随时可能被压缩，只留在对话里的东西会丢。

开发者提出的改动，先判断是改组件、改流程，还是改播放器；不要为了一处改动给别的东西加字段或设置。开发者没要求的设置不要加。

## 组件原型

原型是一个网页，开发者在电脑和手机上都能打开：

- 页面上放这个组件，外面画一圈虚线，标上组件的名字，让开发者看清哪些属于组件；虚线可以开关。
- 组件放在播放器的背景上，就像在题目画面里一样。
- 旁边一排按钮模拟流程发给它的指令，下面一个记录框列出它发出的事件。
- 有讲题和练习两种模式的，能切换着看。
- 流程会怎么排一组这个组件（上下对照、一行几个），每种排法放一份，看大小和对齐是否一致。
- 有声音的，页面上显示声音的状态（是否就绪、为什么没声音），方便开发者在手机上告诉代理哪里不对。
- 一张表写清输入、外观、指令、事件、依赖、谁决定排版、出现在哪里。
- 用到的服务（比如音源）和真实产品一样，单独一个文件，几个原型共用。
- 素材用改编过的例子，不照搬原题。

给开发者看之前，代理先自己检查一遍：

- 在手机、平板、电脑三种宽度下截图看过：没有挤在一起、叠在一起或被裁掉的文字和图形，同一组的组件一样大、该对齐的对齐，页面不左右滚动。
- 每个能点的东西都用脚本点过一遍：点中的是对的，点空白处能清掉，高亮会自己淡掉。
- 每条指令都用脚本跑过一遍，没有报错，发出的事件对。
- 有声音的组件真的发出声音；第一次请开发者在手机上试，手机上没声音时先做一个分步检查的小页面找出原因，再改。
- 没有控制台报错。

## 检查和验收

- `task content` 检查内容文件：格式、引用的流程和组件和资源都在、每句台词都有录音而且和文字一致、素材能解析、答案的格式对。
- `task narrate` 只录台词改过的句子。
- 开发者以家长身份预览每一道题，以孩子身份看完每一道讲题、做完每一道练习，明确说可以，这本书才算做完。
