# POC 的后端和数据

## 技术栈和结构

| 方面     | POC 的做法                                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行时   | Node.js 24，ESM，TypeScript 7                                                                                                                        |
| 框架     | Fastify 5 + TypeBox；不在 Vercel 上时由同一个进程托管前端的静态文件                                                                                  |
| 校验     | 请求体、路径参数、查询串都按 JSON Schema 校验，不做类型转换，对象不许有多余的字段；**响应也写 schema，序列化时多出来的字段会被丢掉**，等于字段白名单 |
| 数据访问 | Drizzle ORM + `pg`。表用 Drizzle 定义，查询大多是手写 SQL，几乎没用 Drizzle 的查询构造器                                                             |
| 迁移     | drizzle-kit 生成 SQL（可以手改），自己写的脚本调 Drizzle 的 migrator 执行，记录在 `__drizzle_migrations`                                             |
| 密码哈希 | `argon2`（原生扩展），Argon2id，m=32 MiB、t=3、p=1                                                                                                   |
| 邮件     | nodemailer，Gmail SMTP                                                                                                                               |
| AI       | 直接用 `fetch` 调 OpenAI 的 REST 接口，不用 SDK                                                                                                      |
| 日志     | Fastify 自带的 pino，加一个自己写的请求日志                                                                                                          |
| 测试     | Vitest；路由用 Fastify 的 inject 测                                                                                                                  |

### 分层

- 每个业务模块（账号和家庭、学习、AI、题库）分 routes（收发、校验、响应头）→ services（业务规则，不依赖 Fastify）→ repositories（SQL）→ domain（纯函数）。
- dependency-cruiser 强制：内层不能引用 routes；repositories 只能被 services 引用；domain 不能引用别的层、Web 框架和数据库驱动；services 只能以类型的方式引用 Fastify；模块之间不互相引用，共用的放 shared；不允许循环依赖。
- 跨模块的东西（例如 AI 要用学习模块的「这道题答对过没有」）都在根目录的约 20 个装配文件里接起来。服务写成工厂函数，依赖靠参数传入，测试时直接传假的，没有依赖注入容器。
- 应用的选项里有约 30 个可选的服务，配置不全时对应的服务就是空的，路由在请求时回答 503「服务尚未配置」。组合根近 300 行全是装配代码。

### 怎么运行

| 方式        | 说明                                                                                                                                                                                                        |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本机开发    | 后端常驻进程加前端开发服务器，`/api` 代理到后端；数据库用 Docker 里的 PostgreSQL 17                                                                                                                         |
| 容器        | 两阶段构建的 Node 镜像，以普通用户运行，同一个进程托管前端。只在本机和多实例测试里用，没有任何环境部署这个镜像                                                                                              |
| Vercel 函数 | 一个 Vercel 项目同时发前端和后端：`/api/*`、健康检查和版本文件路由到一个函数，其余走静态文件和单页回退。函数模块加载时组装好整个 Fastify 应用，处理函数把原始请求交给 Fastify。区域是新加坡，最长运行 30 秒 |

迁移不在后端启动时跑，而是由发布流程在新版本的候选部署建好之后、切换正式地址之前执行。迁移必须向后兼容：旧版本的就绪检查只要求「它自己的最后一个迁移已执行」，所以新加的迁移不会让旧版本变成未就绪。

### 配置

- 端口和主机用 schema 校验，其余是手写的检查。格式不对时启动就失败，但**缺了某项配置大多不报错，而是让对应的功能关闭**（回答 503），要等用户用到时才发现。
- 一个总开关决定建不建数据库连接池，所有用数据库的功能都挂在它下面。
- 网站的准确 origin 用于 Origin 检查和邮件里的链接；生产或 Vercel 上开了注册时必须是 https。
- 托管环境里的数据库连接串只许 `sslmode=verify-full`，**拒绝 Neon 的连接池地址**（因为用了会话级的 advisory lock）。删除清单库必须是另一个数据库。
- 一个 HMAC 密钥既用来把限流的桶名做成伪名，也用来算作答、变化题和孩子注册请求的指纹，一钥多用，换钥会让未完成的重试被拒。
- 孩子 PIN 的服务端密钥（pepper）有版本列，但只认版本 1，轮换没有实现。
- 付费 AI 的总开关不设时**默认开**；每种 AI 服务另有一个「部署者确认这项服务能处理孩子数据」的开关，默认关；月度预算不设表示不限，但发布脚本要求有 AI 密钥时必须设预算。
- 真实发信要另外确认「已核实邮件服务商的条款和额度」，否则启动失败。

## 数据模型

应用库有 20 个迁移、25 张表、3 个枚举；删除清单库另有 1 个迁移、1 张表。有几个迁移手改过（建唯一索引前先撤销多余的 KEY、给已有的孩子补规范化的昵称、插入服务开关那一行、删掉单题安排的表）。

### 关系

```text
family 1─1 parent ─< parent_session
   │         ├─1 email_verification、password_reset
   ├─< child ─< child_session
   │     ├─< book_assignment（书的 id 指向代码里的书单）
   │     ├─< attempt、progress、help_event（按题目 + 版本）
   │     ├─< variation_answer、variation_help（按题目 + 版本 + 轮）
   │     ├─< draft（每个题目版本一条）
   │     ├─< study_day，1─1 study_beat
   │     └─1 child_registration ─1 registration_key
   ├─< registration_key
   ├─< ai_consent（按用途）
   └─< ai_usage（删除后置空）
删除清单库：family_deletions
```

删除家庭就是删掉 `families` 的一行，靠外键级联删掉所有家庭数据。题目和书不在数据库里：题目是共用包里的 TypeScript 插件，书单是一个 TypeScript 文件，编译进后端。

## 接口

### 共同规则

- 写接口都经过同一个守卫：`Origin` 必须等于配置的网站 origin（缺失、`null`、别的都拒绝，不从 Host 或代理头推）；必须带自定义头 `X-Education-Request`；`Content-Type` 必须是 JSON。否则 403「请从本站页面提交」。自定义头加 JSON 类型，让表单和跨源请求发不过来；还没有会话的登录和注册也这样挡，防「登录 CSRF」。
- 登录后的写请求还要 CSRF 令牌，它是会话令牌的 HMAC，随会话一起返回给前端，前端放在内存里；用定长比较。
- 会话 cookie 用 `__Host-` 前缀，`Path=/; Secure; HttpOnly; SameSite=Lax`。家长和孩子共用这一个 cookie，一个浏览器同一时间只能是一种身份。
- 几乎所有回答带 `Cache-Control: no-store`，按会话变化的读接口加 `Vary: Cookie`；每个回答带 `X-Request-Id`。
- 错误统一是 `{ message, reason? }`：自己抛的错用它的状态码和中文文案；框架的校验错误一律是「请检查邮箱和密码格式后重试」，作答、草稿、书架的校验失败也是这句；**所有非 4xx 的错误一律回答 503**「暂时无法完成」；429 带 `Retry-After`。
- 服务开关：有数据库时，所有 `/api/` 请求先查就绪（每个请求一次 SQL），没就绪时 503「网站正在维护」。
- 有的 GET 也要 CSRF 令牌（打开题目、草稿、作答的轮、书架、AI 授权、时区），总览和学习摘要又不要，规则不统一。

| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 注册                       | 密码 15–128 个码点，有一个很小的常见密码表；邮箱已存在时什么都不做，回答完全一样；先算哈希再写库，存在与否耗时相近；注册本身不发信                           |
| 登录                       | 未知邮箱也算一次假的哈希；验证过的家长拿到 7 天的会话，没验证的拿到 15 分钟的受限会话；带着旧 cookie 登录时删掉旧令牌                                        |
| 读会话                     | 不消耗限流额度；每次读都更新最近访问时间（读多写多，也会唤醒 Neon）                                                                                          |

| 找回密码                   | 任何人都能提交邮箱，回答总是「已受理」，并且固定等 **20 秒**才回答（不存在、冷却、超额、投递失败都一样）；30 分钟、一次性                                    |

| 重新验证密码               | 换新令牌，记下输密码的时间，原到期时间不变；有效 5 分钟                                                                                                      |

### 题目和学习

孩子的题目请求都先经过同一个入口：会话和 CSRF → 题目版本在清单上（否则 404）→ 书安排给了这个孩子并且可用（否则 403，带原因「没安排」或「不可用」，不说是哪本书、给了谁）。

| 接口         | 规则                                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 打开题目     | 先试孩子的会话，不行再试家长的；孩子是做题模式，家长是预览模式；只读                                                                       |

| 作答         | 读当前的轮；提交答案、取一条提示、记一次提问                                                                                               |
| 变化题       | 猜数、说理由、提示、提问                                                                                                                   |
| 家长预览作答 | 按同样的规则判，什么都不存                                                                                                                 |
| 学习时间心跳 | 见下文                                                                                                                                     |

### 书架和学习记录

- 家长的书架：书库（能安排、家里还没有孩子有的书）或我的家庭，每页 24 本，带每个孩子是否已安排和做了几道。

### AI 接口

三个接口都要孩子会话、写守卫和 CSRF，限定请求的大小；浏览器断开时取消发给服务商的请求；回答一律是「好了」或「后备，原因是……」（没开、没密钥、没资格、没授权、输入不对、额度用完、不可用、超时、取消），从不回答 5xx。

| 接口       | 说明                                                                                |
| ---------- | ----------------------------------------------------------------------------------- |
| 作答反馈   | 文字或一张 PNG 图；作者的规则能定就不叫模型。**网页上已经没有调用方**               |
| 向老师提问 | 文字（最多 500 字）加这节课到目前为止的记录；记录和课堂内容对不上时回答「输入不对」 |
| 语音转写   | webm 或 mp4，最大 256 KB；校验文件头；不存音频                                      |

## 账号和安全

### 令牌和哈希

- 会话令牌和邮件令牌：32 个随机字节，数据库只存 SHA-256。
- 注册 KEY：16 位 Crockford Base32（80 bit），存 SHA-256。家庭码 12 位，明文存，因为它只用来定位家庭，不授予访问。
- 孩子的 PIN：6 位数字，拒绝全相同和顺序、逆序。存的是 `Argon2id(HMAC-SHA256(pepper, [版本, 家庭, 孩子, PIN]))`。
- 未知账号也算一次同样代价的假哈希，错误文案相同。

### 会话的校验

每次授权都在 SQL 里核对：会话的凭据版本等于账号现在的值，家庭世代等于家庭现在的值，没有过期，没有空闲超时，时间一律用数据库的 `clock_timestamp()`。签发会话的事务会再读一次账号（`FOR SHARE`），密码哈希、版本、世代、验证状态任一变了就不签发，防止「旧密码验证通过」和「重设密码」同时发生时留下旧凭据的会话。

### 限流和资源准入

每次认证类的操作都先经过准入：

1. 进程内最多 2 个同时进行，第 3 个直接 429（决策记录写的是「2 个执行 + 4 个排队、最多等 750 ms」，实际没有排队）。
2. 每次准入从连接池拿一个专用连接。
3. 一个事务里：拿**全站共用的一把事务级 advisory lock** → 删掉 25 小时以前的计数 → 查每个桶 15 分钟和 24 小时的次数，任一超限就 429 → 给每个桶插一行。桶名是 HMAC 伪名，不存原始的邮箱和 IP。
4. 跨实例并发：抢 4 个**会话级** advisory lock 之一，抢不到 429。
5. 算哈希、做业务；结束时销毁这个连接，会话级的锁随之释放。

问题：

- 成功也计数，全站 15 分钟 100 次（含成功），有人乱试时所有人都登录不了。
- 没配可信代理，在 Vercel 上取到的 IP 可能都是入口代理的地址，所有人共用一份来源计数。
- 成功的登录可以一直占着 4 个哈希槽。
- 会话级的 advisory lock 依赖连接一直在：函数被冻结或超时时，连接可能还挂着，槽要等 TCP 断开才释放；每次准入新开一个连接，在 Neon 上要重新做 TLS 握手。
- 全站所有认证尝试排队过同一把锁，人多时是瓶颈。
- 孩子注册和重置 PIN 在持有家庭行锁的事务里算 Argon2，和决策记录「哈希在事务外执行」不一致。

### 发信预算

每个家长每种用途 24 小时 5 次、60 秒冷却；全站合计 24 小时 50 次、15 分钟 10 次。

### 外部 AI 授权

- 两种用途，各有政策版本（日期数字）和中文的披露内容（服务商、发送什么、做什么用、应用保留多久、服务商保留多久），写在代码里。改了披露内容就升版本，旧的授权变成「政策已变」，孩子的请求就不发了。
- 孩子发 AI 请求时，在孩子会话的事务里核对家庭对这种用途的当前版本已经授权；读完服务商的回复后再核对一次会话和授权，家庭删了、孩子退出了、授权撤回了，就不把回复给孩子（但请求已经发出去了）。

### 导出

在持有家庭锁的事务里一次读完。文件开头写明格式版本、生成时间、包含什么和不包含什么；这份清单写在共用的接口约定里，页面在导出前显示的是同一份。响应的 schema 当字段白名单用。

### 删除家庭和删除清单

1. 近期验证 + 输入「删除家庭」。
2. 在持有家长和家庭锁的事务里：先往另一个数据库的删除清单写一行（写不进就 503，家庭不删）→ 再删家庭（级联）。提交以后所有实例都不再认这个家庭的会话。
3. 事务失败但清单已经写了：再单独删一次；还失败就回答「处理中」，每小时的维护任务按顺序补完。
4. 删完在清单上标完成时间；15 天后（备份最长 14 天 + 1 天）从清单删掉。

清单只存内部的家庭 id 和时间，不进应用库的备份，用来在恢复旧备份以后再删一遍。

### 服务开关、备份和恢复

- 服务开关表有一行时服务开放；备份不带这一行，所以恢复出来的库默认是关着的。
- 备份：拿运维锁 → 只读的可重复读事务，导出快照，在同一个快照下数每张表的行数 → 按这个快照 `pg_dump` → 清单（环境、主机、时间、SHA-256、每张表行数）→ age 加密 → 存为 GitHub Actions 的 artifact，保留 14 天。
- 恢复：只采用 `main` 上成功的备份；核对来源环境、校验和、不超过 14 天 → 拿锁、关服务 → 删掉旧的 schema，在一个事务里载入 → 核对开关关着、行数一致 → 迁移到当前版本 → 一个事务里删掉清单里记着的每个家庭、删掉**所有**会话（所有人重新登录）→ 清过期的草稿 → 再读一遍清单确认没有漏掉的家庭，才打开开关。任何一步失败都保持关闭。演练过一次，用时 100 秒。
- 发布、备份、恢复和每小时的维护共用一把**会话级**的 advisory lock，最多等 10 分钟，依次运行。
- 已知限制：备份之后改过的密码和 PIN 会回到旧值。

### 安全响应头

没有。后端不发 CSP、`X-Content-Type-Options`、`frame-ancestors` 等，Vercel 的配置也只设了缓存头。

## 后端的业务规则

### 书和打开题目

- 家长按整本书安排给某个孩子。书单在代码里，每本书有年级、科目、名字、封面、状态，书不删除。
- 能新安排的书：可用，并且至少有一道已发布的题。不可用的书，家长还能看到、能取消，孩子看到变灰、打不开。
- 孩子首页的排序：新书（还没打开过任何一道题）在最前，按安排时间从新到旧；然后是没学完的书，按最近一次作答从近到远，打开过但没作答过的排在这一组最后；然后是学完的；最后是不可用的。

### 最终作答

- 每个题目版本有一个「轮」；答对时这一轮结束，换成新的随机 id。
- 提交时：先拿这道题的学习锁（按「孩子 + 题目 + 版本」算出来的**事务级** advisory lock，草稿、作答、变化题共用，表里还没有行时也锁得住）→ 算内容指纹 → 同一个作答 id 已有记录时，指纹一样就回答原来的结果，不一样就 409 → 轮不对 409 → 用作者的规则判 → 答对并且这一轮用过帮助就是「提示后完成」，否则「独立完成」；答错就是答错；判不了就是判不了（不算错）→ 同一个事务里插入作答、更新四个计数、删掉提交时看到的那个草稿版本（之后新建的草稿不受影响）。
- 提示只返回作者写的（按 id 取，防止 `constructor` 这类名字），每轮每种记一次帮助。向老师提问在问题发出之前先记一次帮助。

### 变化题

- 记在最近一次答对的那一轮名下；又答对一次以后，上一轮的变化题就不收了。
- 先猜数，判出对错就锁定，每轮一个；判不了不记，请孩子再说。再说理由，没说清算答错，可以再说，说清了就锁定。没猜就交理由 409。
- 每道题的状态：猜数和理由各取所有轮里最好的结果，做到过一次就算，后来做差了不改。
- 数据库的部分唯一索引兜底：两次猜数同时到达只记一个。

### 学习摘要和「值得再练」

- 学习摘要：孩子答过或要过提示的每个题目版本，四个计数加提示次数。题目下架了也保留记录。
- 「值得再练」：把一道题所有版本加起来，答错 2 次以上并且从没独立答对过。任何版本独立答对过就算完成，出新版本也不会再回到列表。
- 总览里每天每道题的状态取当天最好的结果；SQL 用 `AT TIME ZONE` 把时刻换成家庭时区的日期。

### 学习时长

- 心跳每 30 秒一次；两次心跳间隔超过 90 秒说明中间停了，这段不算；第一次心跳和时间倒退也不算，只把时钟设到这次。
- 算出来的整秒按家庭时区的本地午夜切开，分别加到各自的日子上（夏令时那天 23 或 25 小时也对）；不足一秒的部分留给下一次，两个标签页同时发心跳也不丢不重。
- 事务里锁住孩子的时钟行，时间用数据库的 `clock_timestamp()`，各服务器一致。改家庭时区不改写已经记下的日子。

### 时区

家庭时区是 IANA 名，永远不用固定的偏移。日期运算（加天、相差天数、某天的开始时刻、某时刻的本地日期）写在前后端共用的包里，处理午夜被跳过的时区。风险：JS 用 Node 的 ICU，SQL 用 PostgreSQL 的 tzdata，两边的数据版本不同步时边界上可能对不上。

### 一致性和并发

- 一切靠 PostgreSQL 事务，不用队列，不用 Redis。默认的隔离级别，靠显式的锁保证顺序。
- 固定的加锁顺序：家长请求先锁家长、再锁家庭、再锁会话；孩子请求以共享锁锁家庭和孩子，再更新会话。有专门的集成测试证明排在删除后面的家长请求不会死锁。
- **所有家长请求（包括只读的总览）都对家庭行加排他锁**，同一家庭的家长请求串行，并挡住孩子的请求。
- 幂等：作答、变化题、孩子注册都用「浏览器生成的 id + 带密钥的内容指纹 + 唯一约束」，重试回答原来的回执，同一个 id 换了内容就 409。
- AI 调用不在数据库事务里等：短事务里预留额度 → 在孩子会话的事务里只**发出**请求，不等结果，事务马上提交 → 事务外读回复 → 单独一条 UPDATE 结算 → 再核对一次会话和授权。
- 每条语句 3 秒超时。

## 外部集成

### 邮件

- 适配器把发信结果分成五种：已接受、可重试、被拒、授权失败、未知。邮件正文是中文的纯文本和 HTML，没有孩子的信息，没有追踪像素和外部资源。
- 服务商：个人 Gmail 加应用专用密码，SMTP 465，TLS 1.2 以上，校验证书；每封信新建一个连接；整体 12 秒截止。
- 结果分类：认证失败 → 授权失败；5xx → 被拒；4xx 或数据之前的命令失败 → 可重试；数据之后断开 → 未知，不能证明没送达，所以不盲目重试。
- 发信意图持久化：令牌用 AES-256-GCM 加密暂存，只在「可重试、3 次以内、没过期」时保留，其余情况发完就置空。没有后台队列，发信在请求里同步进行。
- 只测过 126.com 的收件箱，QQ 和 163 没测。

### AI 服务

- 模型和单价写死在代码里。请求关推理、限定最大输出、不让服务商保存、流式返回、输出用严格的 JSON schema；请求体有上限，回复流最多读 64 KB，只认恰好一条消息、一段文字。
- 提示词告诉模型孩子的话只是数据，要它自己报告提示注入；不确认也不否认孩子的答案；一句不超过 60 字，不含链接、HTML、Markdown。
- 回复当不可信的数据：必须恰好符合 schema；句子里不能有 HTML、实体、反引号、链接、控制字符；自报注入时换成固定的一句；句子里有「对、不对、没错、正确」这类判定时换成「这个要你自己来核对哦」。AI 永远不写作答、进度和权限。
- 计费和限额：先判部署能不能用（开关、密钥、资格），再建请求，再预留——一个事务里按「最大输入 + 最大输出」的价钱预留，要求全站本月已花加这次不超过预算、本月没有越界的回复、家庭和孩子没超过每分钟的次数。结算：服务商拒绝就释放；有用量并且在约定范围内就结算；用量超出约定的上限就标为越界，**全站本月剩下的时间暂停付费 AI**；拿不到用量就保留预留的金额。转写按实际时长计费，不算越界，否则一个孩子就能关掉全站一个月。
- 整个调用 10 秒，客户端断开就取消，不自动重试。每小时汇总上一个整点的用量，失败过半或本月有越界时开告警。

### 日志

- 关掉 Fastify 自带的请求日志，每个请求自己写一行：方法、路由模式（不是原始地址）、状态码、耗时、结果分类、错误码。不记请求头、cookie、请求体、查询串和异常消息。
- 数据库错误只记 SQLSTATE 和允许列表里的连接错误码，沿着错误的 cause 链找；错误消息只用来认出超时，绝不写进日志，因为里面可能有连接串、参数和孩子的输入。
- 另外遮挡 authorization、cookie 和 set-cookie。

### 告警

没有监控服务。告警就是开一个 GitHub issue：定时的就绪探测、AI 用量、发布、备份、维护和恢复任务失败各算一个来源，失败时开 issue 并指派给值班的人，恢复时评论并关闭。Vercel 免费版的运行日志只保留很短时间，没有导出。

## 和意图的出入、缺陷、死代码

### 和决策记录的出入

- 哈希的并发：设计是排队等待加有过期时间的租约，实际没有排队，租约换成了没有过期时间的会话级锁。
- 「只信任受控入口的代理地址」没做到。
- pepper「可以受控轮换」，实际只认一个版本。
- 「家长可以查看和撤销设备会话」没做。
- 「恢复以后换一个数据世代，旧设备待提交的请求先核对」没做，靠草稿的版本冲突兜底。
- 架构文档里的表名、设计文档里的导出格式版本，都和代码对不上。

### 缺陷和风险

1. 一个人就能挡住所有人登录（见上文的限流）。
2. 会话级的 advisory lock 和事务模式的连接池不兼容，所以只能用 Neon 的直连地址；函数实例多时会占满直连的连接数。
3. 没有安全响应头。
4. 所有非 4xx 都回答 503，程序缺陷和真正的不可用在客户端看起来一样。
5. 框架校验失败的文案永远是「请检查邮箱和密码格式」。
6. 哪些 GET 要 CSRF 令牌，规则不统一。
7. 家长的每个请求都对家庭行加排他锁。
8. 找回密码固定等 20 秒，每个请求占一个函数 20 秒，容易被刷到函数并发耗尽。
9. 每次读会话都写一次会话行。
10. 过期的会话只在登录时顺手删，没有定时清理。
11. 一个 HMAC 密钥多种用途。
12. 缺配置时功能静默关闭，而不是启动失败。
13. 孩子昵称和家长邮箱明文存储。
14. 题目内容是代码，作为公开的静态文件发出去（判定规则只在服务器上，这一点做得对）。

### 死代码和遗留

作答反馈的接口和网页上的画板没有调用方；一个永远回答「没发信」的占位邮件适配器；没有调用方的预留费用函数；不再使用的草稿修订号列；名不副实的限流计数表；用 Supabase 时留下的行级安全和撤权，在 Neon 上不起作用。
