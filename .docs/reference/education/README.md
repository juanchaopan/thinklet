# 参考项目 education（POC）分析

## 分析对象

education 是 thinklet 的 POC（原型版本），产品名叫「小小探索家」：一个中文的儿童交互式解题网站。代码在公开仓库 <https://github.com/juanchaopan/education>，主要用 TypeScript 写。

- 时间：集中开发在 2026-11-04 到 2026-11-16，约 12 天；之后到 2026-11-20 只有依赖更新。文中的统计截至 2026-11-20。
- 开发方式：全部代码由 AI 代理写（Claude Code 和 OpenAI Codex）；维护者只有一人，负责确认需求、看样稿、试听、在测试环境上试用和批准合并。
- 规模：约 3,200 个文件；`main` 上 146 个提交（不算合并提交是 144 个）；151 个 PR；117 个 issue（23 个开着）；18 份架构决策记录；43 份逐个 issue 的验收记录；1,362 张截图基准。
- 分析的版本：`main` 的最新提交（2026-11-16），以及 7 个 spike 分支（托管、账号安全、邮件投递、AI 模型、浏览器语音和触摸、作答一致性、老师讲解动画）。还读了全部 issue 和评论、PR 标题和抽查的 PR 描述、CI 的运行记录和仓库设置，并只用 GET 请求看过线上的测试环境。

分析只读：POC 的仓库、它的测试环境和它用到的外部服务都没有改动。

## 一句话结论

POC 证明了「每道题一部有声互动短片，孩子动手发现，最后开口作答」这种教法能做得很细，账号、家长空间和数据保护也做得扎实。但它把每道题写成一份专属的代码，12 天只做出两道题，没有一道经过真实孩子的验证；它从没上过生产，也没在中国大陆测过访问；AI 用的 OpenAI 不对中国大陆提供服务。

## 主要发现

### 做得好的

- **教学原则**：结论前后一致，量先于符号，每一幕的开场白都能单独听懂，关键时刻必停但不停在答案上，按解法和年级选表示方式。这些原则来自维护者多轮退回分镜，和技术栈无关（[teaching.md](teaching.md)）。
- **课堂流程**：一种流程写清六件事——怎样往下走、最后交什么、怎么判、变化题怎么做、记录什么、学习摘要怎样显示；流程只从真题里提炼，不预先编。
- **判定和记录**：判定只在服务器上做；判不了永远不算错；多个解的题按集合判；模型从不判对错；只存结果，不存孩子的原话。
- **账号和数据保护**：不透明的会话令牌，只存哈希；写请求有 Origin 检查、自定义头和 CSRF 令牌；敏感操作要在 5 分钟内重新输过密码；作答幂等；导出带「包含什么、不包含什么」的清单；删除家庭用外键级联；外部服务的授权按用途和政策版本记录（[backend.md](backend.md)）。
- **测试和检查**：集成测试连真实数据库，专测并发、竞态、跨实例和部分失败；架构检查分析到 0 个模块时判失败；一整套让截图稳定的做法；触控尺寸、缩放、减少动态效果、键盘顺序的无障碍检查。

### 问题

- **题目即代码**：一道题 2,300–3,300 行代码（含测试），加几十段预录旁白，还要维护者确认分镜、试听、看录像。题目、答案的文字、录音和图片都是公开的静态文件，猜到地址就能下载。
- **核心假设没验证**：没有真实的孩子用过；语音识别在测试环境上从没成功过；「掌握」怎么判始终没定。
- **合规缺口**：产品面向中国大陆的孩子，但测试环境在新加坡，AI 用 OpenAI，邮件用个人 Gmail，旁白用条款不明的微软在线朗读接口，题目取自第三方教辅并放在公开仓库里；没有隐私政策，没考虑《个人信息保护法》、ICP 备案和数据出境。
- **没有安全响应头**：前后端都没有 CSP、`X-Content-Type-Options`、防点击劫持等响应头。
- **流程走了样**：中高风险 PR 的批准标签由代理用维护者的令牌自己加，最快一次 28 秒批准了 2,500 行；CI 里的 AI 评审配好了却从没运行；定时任务严重延迟——每小时的维护每天只跑 3–5 次，每小时两次的健康探测每天只跑 2–5 次，每天的备份晚几个小时，文档里的清理、告警和备份间隔都不成立（[delivery.md](delivery.md)）。
- **规模不相称**：目标只有 10 个家庭，却有 1,362 张截图、约 1 GB 的仓库历史、36 分钟的 PR CI，和一条为绕开平台限制而写的发布触发链。
