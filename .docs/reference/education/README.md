# 参考项目 education（POC）分析

## 分析对象

education 是 thinklet 的 POC（原型版本），产品名叫「小小探索家」：一个中文的儿童交互式解题网站。代码在公开仓库 <https://github.com/juanchaopan/education>，主要用 TypeScript 写。

- 时间：2026-11-04 到 2026-11-16，约 12 天的集中开发，之后只有依赖更新。全部代码由 AI 代理写（Claude Code 和 OpenAI Codex），维护者只有一个人，负责确认需求、看样稿、试听、在测试环境上试用和批准合并。
- 规模：约 3,200 个文件；`main` 上 144 个提交；151 个 PR；117 个 issue（23 个开着）；18 份架构决策记录；43 份逐个 issue 的验收记录；1,362 张截图基准。
- 分析的版本：`main` 的最新提交（2026-11-16），以及 7 个 spike 分支（托管、账号安全、邮件投递、AI 模型、浏览器语音和触摸、作答一致性、老师讲解动画）。还读了全部 issue 和评论、PR 标题和抽查的 PR 描述、CI 的运行记录，以及仓库设置。
- 线上测试环境：只发 GET 请求看过，正常运行最新版本。没有注册账号，没有改动任何数据。

分析只读。POC 的仓库、它的测试环境和它用到的外部服务都没有改动。

## 一句话结论

POC 证明了「每道题一部有声互动短片、孩子动手发现、最后开口作答」这种教法能做得很细，账号、家长空间和数据保护也做得扎实。但它把每道题写成一份专属代码，两周只做出两道题，没有一道题经过真实孩子的验证，从没上过生产，也没在中国大陆测过访问。AI 用的是 OpenAI，而 OpenAI 不对中国大陆提供服务。thinklet 值得拿走的主要是教学原则、判定和记录规则、账号和数据保护的设计、几个测试和检查的做法。不该照搬的是「题目即代码」的出题方式，以及和 OpenAI、Gmail、edge-tts 绑定的做法。

## 主要发现

### 做得好、值得借鉴的

- **教学原则**：结论前后一致（同一样东西一张图、一个叫法、一个量词），量先于符号，每一幕的开场白都能单独听懂，关键时刻必停但不停在答案上，按解法和年级选表示方式。这些原则来自维护者多轮退回分镜，和技术栈无关。
- **课堂流程**：一种「流程」写清六件事：怎样往下走、最后交什么、怎么判、变化题怎么做、记录什么、学习摘要怎样显示。流程只从真题里提炼，不预先编。这和 thinklet 的「题型模块」几乎是同一个概念。
- **判定和记录**：判定只在服务器上做；结果分「对、错、判不了」，判不了永远不算错；多个解的题按集合判；模型从不判对错；只存结果，不存孩子的原话。
- **账号和数据保护**：不透明的会话令牌、只存哈希；写请求有 Origin 检查、自定义头和 CSRF 令牌；敏感操作要在 5 分钟内重新输过密码；作答幂等；家庭数据导出带「包含什么、不包含什么」的清单；删除家庭用外键级联；外部服务的授权按用途和政策版本记录。
- **测试和检查**：集成测试连真实数据库，专测并发、竞态、跨实例和部分失败；架构检查分析到 0 个模块时判失败；截图稳定的一套做法；无障碍的额外检查（触控尺寸、缩放、减少动画、键盘顺序）。

### 问题和教训

- **题目即代码**：一道题 2,300–3,300 行代码（含测试），加几十段预录旁白，还要维护者确认分镜、试听、看录屏。两周上线两道题，第三道一直没做。题目、答案文字、录音和图片都作为公开的静态文件发出去，猜到地址就能下载。
- **没有验证核心假设**：没有真实孩子用过；语音识别在测试环境上从来没成功过；「掌握」怎么判始终没定。
- **合规缺口**：产品面向中国大陆的孩子，但测试环境在新加坡，AI 用 OpenAI，邮件用个人 Gmail，旁白用条款不明的微软在线朗读接口，内容取自第三方教辅（学而思）并放在公开仓库里。没有隐私政策，没有考虑《个人信息保护法》、ICP 备案和数据出境。
- **没有安全响应头**：前端和后端都没有 CSP、`X-Content-Type-Options`、防点击劫持等响应头。
- **流程走了样**：中高风险 PR 的「人工批准」实际由代理用维护者的令牌自己加标签，最快的一次在 28 秒内批准了 2,500 行改动；CI 里的 AI 评审配好了却从没运行过；GitHub 的定时任务每天只跑 3–5 次（设定是每小时），文档里的备份和告警间隔都不成立。
- **规模不相称**：目标只有 10 个家庭，却有 1,362 张截图、约 1 GB 的仓库历史、一次 36 分钟的 PR CI，以及为了绕开平台限制写的发布触发链。

## 对 thinklet 的提醒

这些提醒在 [verdicts.md](verdicts.md) 的最后一节有更详细的说明。

- 第一个题型的 issue 先定「题型是代码、题目是数据」的边界，以及内容怎样按权限、按作答进度下发，答案不提前出现在浏览器里。
- 账号的 issue 可以参考 POC 的会话、CSRF、密码哈希、重新验证和发信意图的设计，但限流要用 POC 修订后的规则（只计失败，不设全站封锁），只用事务级锁，并配好可信代理。
- 用到声音、麦克风、AI 或邮件时，先确认服务在中国大陆可用、条款允许用在儿童身上，并取得家长同意。
- 人工批准只能由用户本人给；不要把有时效要求的任务放在 GitHub 的定时任务上；控制截图基准的数量。
