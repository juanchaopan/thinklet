# POC 的前端

## 规模

- 前端约 850 个文件：业务代码约 21,600 行 TypeScript，样式约 5,800 行，178 个测试文件约 830 个用例，89 个 Storybook story 文件，89 段录音，19 张图。
- 家长和孩子的外围页面做得规整，分层和各种状态都覆盖到了。课堂引擎很精细（类型从题目定义一路检查到页面，失败处理细到每一种情况），但每道题都是手写代码。

## 技术栈和结构

### 技术栈

- React 19 单页应用；React Router 7；TanStack Query 5 管服务器数据；接口约定用 TypeBox。
- 构建用 Vite 8，自己写了三个插件：
  - 把发布的提交号写进页面的 `<meta>`，打开着的页面靠它发现新版本；
  - 往 `<head>` 注入一段**内联脚本**，在第一次绘制前设好日夜主题；
  - 构建时扫描源码里出现的中文字，从 7.4 MB 的中文标题字体里子集出约 187 KB 的字体文件。
- 样式用 CSS Modules 加 CSS 自定义属性（设计令牌）；Storybook 10；代码规范用 Oxlint（因为 typescript-eslint 跟不上 TypeScript 7），格式用 Prettier，重复代码用 jscpd。
- 没有国际化库，界面文字直接写在组件里；没有 Service Worker；没有错误监控。

### 分层

```text
app/               外壳：路由、布局、题目页登记、发布更新、主题
shared/ui/         共用的展示组件（按钮、卡片、图标、书卡……）
shared/lib/        纯函数和通用的 hooks
features/family/   账号、孩子的书架、家长空间
features/learning/ 课堂：公共画面部件、每道题的文件夹、不依赖 React 的引擎、语音、画图、数据访问
features/library/  题目页的外壳
```

- 页面（容器）调数据访问的 hooks，处理加载、出错和空状态；展示组件只收参数、发回调。
- 没有全局状态库：服务器数据都在 TanStack Query 里，题目里的状态放在页面或交互控制器里。

### 架构规则

用 dependency-cruiser 强制：

- 展示组件不能引用数据访问层、页面和外壳，也不能用数据请求的库；
- 功能之间互相隔离，共用的东西不能反过来引用功能；不允许循环依赖；
- 一道题的文件夹不能引用另一道题的；一道题只能读自己那份课堂内容；
- 题目的代码只能按需加载，所以首页的包里没有任何题目；
- 判定规则所在的插件不能进浏览器；
- 外面包了一层：dependency-cruiser 一个模块都没分析到时也算失败（新版 TypeScript 下它会「0 个模块、0 个违规」地静默通过），并支持已知违规的基线。

### 请求

- 请求的封装有三套（家长和账号一套、课堂一套、几处直接写 `fetch`），请求头、超时和错误文案各不相同。
- 回复一律先按共用的 schema 校验，不合格就当失败，页面从不处理认不出的回复。
- 写请求带自定义头和 CSRF 令牌；10 秒超时。课堂里任何接口回答「没安排」或「不可用」时，题目页重新问一遍能不能打开，换成对应的提示。
- 作答幂等：每次作答在浏览器里生成一个 UUID，回复丢了重试时原样再发，只认同一个 id 的回执；作答挂在服务器发的「轮」上，轮冲突时重新读一遍轮，不重发。
- AI 请求同一时间只发一个，超时就转成后备的引导，孩子可以主动放弃，放弃以后迟到的回复一律忽略。
- 有的请求缓存键里放了带函数的对象，缓存键实际靠 CSRF 令牌区分，很脆弱。

### 样式、字体和图标

- 设计令牌按用途命名（背景、表面、文字、主色、强调色、危险、成功、阴影），白天和晚上各一组；题目页的控件只用一组和主题无关的「烟色玻璃」令牌。触控目标 44px，凸起的深度 3px，动效时长和缓动都是令牌。
- 标题用自托管的霞鹜文楷子集（不连境外的字体服务），正文用系统黑体。运行时才出现的字（例如昵称）不在子集里，逐字回退到系统字体；书名和题目只在数据库里时，这种子集化覆盖不到。
- 图标是自己画的 SVG（24 格、2px 圆头描边），不用图标库，也不用表情符号代替。

### 外壳

- 三种布局：普通页面、只给 404 用的站点布局、不套外壳的全屏题目页。
- 主题：按家庭时区算 6:00–18:00 是白天，其余是晚上；页面开着时到点就切，颜色在 1.2 秒内过渡；开了「减少动态效果」就直接切。
- 发布更新：每分钟（以及页面可见、得到焦点、恢复联网时）读一次版本文件，和页面里的版本比。发现新版本时，按「现在刷新会丢什么」排出先后：短片正在讲 > 有没保存的输入 > 正在保存 > 正在显示只出现一次的东西（例如刚生成的 KEY）> 可以刷新。都没有时自动整页刷新，每个版本只自动刷新一次，否则显示提示。题目的代码块加载失败时（多半是发了新版本、旧文件没了），显示「重新打开」并立刻查一次版本。

## 课堂引擎

### 一道题的网页代码

一道题由什么组成，见 [teaching.md](teaching.md)。网页这边每道题要写：外观（片名、讲课角色和站位、道具的范围、调色板、SVG 的颜料和符号、点缀）；配好录音的台词稿和每一幕的取景；这道题的状态机（每一幕开始时和孩子每次操作后，返回下一个状态、要说的话、提示音、说完进哪一幕）；画面快照；能拿起和推动的道具；作答；变化题；结论板上的图；SVG 场景组件；每句一个 mp3 和一份录音清单。

各题的网页代码（不含测试）：菜园天平 978 行，数轴追及 2,007 行，模板 362 行；公共部件约 9,200 行。**题目和题型是同一个东西**，没有「一个题型配多道题的数据」这一层。

### 运行时

- 每道题的定义构造一次页面组件，页面里的类型都是这道题自己的（状态、幕名、台词、操作）。这个定义类型有 6 个泛型参数，层层往下传。
- 引擎的核心不依赖 React：一次反应 = 新的状态 + 要说的几句 + 提示音 + 说完进哪一幕。按顺序说几句，两句之间停 310 ms；被新的一轮打断时停下；一句放不出来时一直等孩子重听，不跳过。
- 进入短片的那一下点按，同时解锁声音、请求全屏（不支持时只撑满窗口）、开始计学习时间。

### 画面

- 舞台的层次：外围是模糊铺满的背景；背景层每一幕按相机缩放和平移取景；上面是 1200×675 的 SVG 世界（讲课角色、题目的场景、拖动时的影子）；再上面是暗角、片名卡和控件。
- 控件用「位置名」标明放在哪（工具、提示、字幕、作答、提示露珠、提问、话筒、角落），由舞台的样式按画框的形状摆。
- 横竖屏：舞台是一个尺寸容器，用容器查询分横竖。横屏时背景和道具当作一幅画铺满；竖屏时只有背景铺满，道具按宽度和控件留下的高度缩放。用 visualViewport 把控件挪到手机键盘上面。
- 道具是 `role=button`、可以用 Tab 走到、带读屏标签；不论画多小，手指能点到的范围至少直径 60 个世界单位。

### 触摸、拖动和键盘

- 拖动只认主指针、左键，用 pointer capture，移动超过 6px 才算拖，处理系统取消，拖完以后吞掉随后的那次点击。
- 用 SVG 的屏幕变换矩阵把屏幕坐标换成世界坐标；道具可以拖到目标上，也可以先点道具再点目标。
- 键盘：回车和空格等于点按，左右方向键推动道具。
- 必停推进：一幕里的量只能在「这一幕开始的地方」和「必停点」之间，拖得再快也停在停点；点一下或按一下方向键走一整步。数轴追及靠它让孩子在第 1、2、3、10、11、12 秒停下，而不会停在答案 6 或 14 上。
- 显示的量按固定速度一帧帧走到新值；孩子按住拖动时或开了「减少动态效果」时一步到位。
- 早期的画图作答（Canvas 加 Pointer Events）还在，没有题目在用，却一直维护着测试和截图。

### 旁白和声音

- 没有用浏览器的语音合成和语音识别。旁白都是预先生成的 mp3。
- 一节课只有一个音频播放器，由开始的那一下点按解锁，前后两句不会重叠。失败分四种：被浏览器拒绝、11 秒还没开始播（或网络错误）、解不了码、被系统中途暂停（例如来电）。一句放不出来时这一幕停住，重听按钮变色、闪着等孩子点，字幕自动打开。关掉声音时用静音照常播放，每句照样按结束的时间往下走。
- 进题时下载本课**全部**录音，下载完才能开始（数轴追及 67 段、约 3.5 MB，在大陆的移动网络上可能要等很久）。播放仍用原地址，靠浏览器的 HTTP 缓存；不用 blob 地址，因为有些 WebKit 版本拒绝播放。
- 提示音用 Web Audio 的振荡器合成，不是音频文件。
- 字幕只显示最新的一句，来源有旁白、作答、提示和提问四种。

### 语音输入

- 用 MediaRecorder 录音，格式依次试 webm/opus、webm、mp4（Safari）。两种模式：按住说话；页面自己开麦，说完安静下来算结束（音量阈值 0.02，静 1.5 秒算说完，8 秒没出声就关）。不到 500 ms 的录音不发；麦克风用完马上释放；音频只在内存里。
- 一节课只有一个麦克风，轮流用；孩子按住提问时，自动开的麦要让出来。
- 录完转成 base64 发给服务器，由服务器调转写服务。只有孩子确认过的非空文字才往下传。
- 从转写文字里读出数：阿拉伯数字、全角数字、一百以内的中文数字；排除「一样」「一共」「一起」这类不表示 1 的词；有单位时按单位前面的数读；「六秒和十四秒」读成两个数；读不出时请孩子再说一次。
- 实际效果：测试环境上电脑 Chrome 每次都「没有听出来」，从没成功过；服务器的日志不记转写服务失败的原因，排查不了。

### 作答、提示、提问

- 课堂流程决定作答部分，类型检查保证每种流程都有对应的作答部分。
- 作答那一幕：旁白讲完响一声，麦克风自己打开 → 孩子说 → 显示「我听到 9 根」，配一个确认和一个重说 → 确认后提交 → 判定。用不了麦克风时才换成一排数字按钮（一行最多 6 个）。家长预览一律点选。答对后显示星星和「接着看」，删掉草稿。
- 提示放在作答那一幕，以及变化题从猜之后到说理由的几幕；剩几次就显示几只萤火虫，每一条都记到服务器。
- 每一幕都有按住提问的话筒。问题带着这节课到目前为止的记录（只用课堂内容声明过的标识和数，超过上限时只留最近的）。老师的回答只有文字，显示在字幕里；超时或失败时，字幕说这一幕自己的引导语。

### 结论板和推导板

- 结论板：一排玻璃胶囊，每条结论用题目的道具图画出「一样多的几份」，中间是等号，不写数字和汉字。量小的一件件画，按道具的形状摆，最多两行；成组的画在框里；太多时写「k×」。用到的那条描金边、慢慢呼吸；变化题的「假如」是虚线框，「那么」是实线框。读屏读完整的一句。
- 推导板：SVG 世界里的一块玻璃板，当前一步大字，上一步淡显在上面，分情况时一种情况一行，下面一行是读法。数轴追及的每一步：每秒追回 2 − 1 = 1 格 → 蓝车领先 = 10 − t → 10 − 11 = −1 → 距离 = |10 − t| → |10 − t| = 4 → 蓝车在前时 10 − t = 4、黄车在前时 10 − t = −4 → t = 6 或 t = 14。

### 草稿、学习时间、预览

- 每到一个算进度的幕就存草稿，带版本号；冲突时让孩子选「从上次的地方继续」还是「从头做」。草稿只记到哪一幕，回来时从那一幕的开头重来。
- 学习时间的心跳每 30 秒一次（计时规则见 [product.md](product.md)）。
- 家长预览：同一段短片、工具和结论板；作答点选，服务器照样判；没有话筒、提问和草稿，什么都不记录。

## 视觉、无障碍和截图

### 视觉语言

- 白天「手作工作台」：暖米色纸纹、象牙白卡片、森林绿的主按钮。晚上「暮光剧场」：深墨绿、半透明玻璃卡片、带光晕的暖金按钮。两套主题只换颜色、底纹、阴影和光晕，版式、字体、圆角和动效都一样。题目页不随主题变。
- 能按的东西都是同一种凸起：一层面、下面 3px 的深色边、柔和的投影；按下沉 2px；不能按时变平。输入框和进度条的槽是凹下去的。书是立体的，有书脊的明暗和书页的边。
- 文字从简：口号和安慰话删掉；加载用三颗跳动的圆点，「正在……」只给读屏；隐私、授权和不可撤回的说明放在做决定的那一步；次要细节折叠在「?」里。
- 动效：按下 120ms；悬停 250ms；页面进入时各区块依次上浮，600ms，间隔 80ms；主题切换 1.2s。打开「减少动态效果」时只去掉动效，凸起和投影保留。

### 无障碍检查

每个 story 和每个页面截图之后都跑 axe（WCAG 2.0、2.1、2.2 的 A 和 AA），另外检查：

- 键盘：桌面上逐个按 Tab，每个控件都能到，焦点处至少 2px 的轮廓，第一站是「跳到主要内容」；
- 减少动态效果：打开以后页面上没有任何动画和过渡；
- 触控：平板和手机视口里每个控件的宽和高都不小于 44px；
- 缩放：320px 宽时不横向滚动；640px 宽、文字放大到 200% 时也不横向滚动；
- 不只靠颜色：结果状态在 status 或 alert 区域里有文字。

真机上的触摸、读屏和声音没有验证过。

### Storybook 和截图

- 393 个 story，覆盖每个部件的正常、空、加载中、失败、长文字等状态。每个视口截 393 个 story 加 18 个关键部件的晚上版（411 张），再加 34 个页面状态和其中 9 个的晚上版（43 张）；桌面、平板、手机三个视口，共 1,362 张。大部分是和视口无关的小部件在三个视口各存一份。
- 页面截图的测试把每一个接口请求的回答都固定好，表里没有的请求会让测试失败。
- 只在固定版本的官方 Playwright 镜像里跑，版本号取自锁文件。
- 让截图稳定的做法：时钟固定在白天 10:00 和晚上 20:00；加一张样式表，把所有动画和过渡的时长和延迟设为 0；等图片解码完、字体加载完；整页隐藏再显示，强制重新排版和绘制，等两帧，并确认没有还在跑的动画；`deviceScaleFactor: 1`；关掉 LCD 亚像素抗锯齿；CI 里偶发失败也算失败；普通运行不写基准。

## 测试

- 单元和组件测试：Vitest 加 jsdom 加 Testing Library；音频、录音、全屏都有测试替身。有两个组件测试在全量并行时偶尔超时。
- 端到端：浏览器是 Chromium 桌面和模拟 iPhone，旁白的用例另跑 WebKit；没有 Firefox。放音检查在页面里包装 `HTMLMediaElement.prototype.play`，逐句核对每段录音按台词稿的顺序从头播到尾，没有跳过也没有失败。
- 每道题一段带声音的审查视频，给人看。
- 测试的种类和数量见 [delivery.md](delivery.md)。

## 和文档的出入、正文以外的缺陷

- 决策记录写的是 ESLint，实际用 Oxlint；写主题「按设备本地时间」切换，实际按家庭时区；写老师「用文字和语音」回答，实际只有文字；把浏览器自带的语音识别列为候选，实际只做了服务器转写。
- 架构文档说前端「不得接触答案判定的私有规则」。判定规则确实只在服务器上，**但答案的文字已经在浏览器的包里了**：结论板上的「一共 9 根黄瓜」、揭晓的旁白「一共六根」、推导板上的「t = 6 或 t = 14」，都在按需加载的公开 JS 里，录音和背景图也是公开的静态文件。
- 整个仓库没有 CSP 和 Permissions-Policy；首屏的主题脚本是内联的，不能和只允许本站脚本文件的 CSP 共存。
- 只给 Storybook 用的辅助代码和测试数据放在产品代码目录里。
- 几乎每个函数都有一段叙事式的注释；命名用了一套电影比喻（film、shot、tale、arrive、respond、say、chime），新人和 AI 都要先学这套词才读得懂。
- 和规模不相称的复杂度：目标 10 个家庭，却有按 IANA 时区、照顾夏令时的主题切换，带五级优先级的「能不能刷新」登记，1,362 张截图，一份 117 KB 的部件文档。
- 复杂度热点：舞台（组件 245 行、样式 524 行）、结论板的样式（235 行）、泛型的页面工厂（245 行）、播放状态机（239 行）、录音（241 行）、开口作答（210 行）、家长书架的数据层（292 行，分页、乐观更新、几个书架之间同步）、数轴追及的 SVG（四个文件各 160–260 行）。重复是结构上的：每道题都要写一遍同样的四件套（状态机、画面快照、道具、场景），jscpd 发现不了。
