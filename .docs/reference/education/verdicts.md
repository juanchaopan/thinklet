# POC 的技术做法对 thinklet 的结论

每个做法给一个结论：

- **值得借鉴**：写明在 thinklet 里怎样用；
- **不适合**：写明为什么；
- **thinklet 已另定**：注明 thinklet 的决策记录编号（`.docs/decisions/`）。

thinklet 的前提见 `.docs/brief.md` 和 `.docs/architecture.md`：

- 用户和范围：孩子 3–18 岁，没有独立账号，用家长建的档案学习；内容只由平台团队制作；题型是独立模块，加新题型不改平台；教学和练习分开；首版不做分步引导和提示、趣味激励、错题本。
- 部署和合规：生产在中国大陆，要 ICP 备案，遵守《个人信息保护法》和《儿童个人信息网络保护规定》。
- 技术栈：Angular 加 NestJS，PostgreSQL（JSONB）加 S3 对象存储；共用包只放接口约定；严格的 CSP。

## 给 thinklet 后续 issue 的提醒

- **第一个题型的 issue**：先定「题型是代码、题目是数据」的边界，内容怎样按权限、按作答进度下发，答案怎样不提前出现在浏览器里。把 POC 的课堂流程「六件事」当作题型 design 文档的骨架，教学原则写进内容制作规范。
- **家长账号的 issue**：回到 architect 步骤时，会话、CSRF、Argon2、重新验证、发信意图都可以照 POC 的设计；还要定限流的存储（只能用事务级的锁）、可信代理的配置、国内的邮件服务商、同意记录的数据模型。POC 踩过的坑一开始就避开：只计失败、取真实的客户端地址、成功的登录也有上限。
- **孩子档案的 issue**：要定孩子个人信息的加密方式和密钥；孩子怎样在设备上进入档案，在 design 步骤定。
- **家长看进度的 issue**：结果分三种、只存结果；学习时长的心跳和按本地午夜切分；读取的接口不加排他锁。
- **用到声音、麦克风、AI、邮件时**：先确认服务在中国大陆可用、条款允许用在孩子身上、取得家长同意；CSP 加 `media-src`，Permissions-Policy 按需打开 `microphone`；TTS 选条款明确的。
