# POC 的技术做法：结论

每个做法给四种结论之一：

- **值得借鉴**：和 thinklet 的目标相符，换到 thinklet 的技术栈也成立；
- **部分借鉴**：思路可取，但具体做法不适合；
- **不适合**：和 thinklet 的目标、合规要求或规模不符，或者在 POC 里就证明有问题；
- **thinklet 已另定**：thinklet 已经有了不同的决定，括号里是决策记录的编号（`.docs/decisions/`）。

对照的是分析时（#5）thinklet 的 `.docs/brief.md`、`.docs/architecture.md` 和决策记录。文中所有「可以……」只说明这个做法在 thinklet 的技术栈里大致是什么样子，不是 thinklet 的决定。

## 教学和内容

### 教学和内容：值得借鉴

- **课堂流程（一种流程写清六件事，只从真题里提炼，新流程必须同时定下学习摘要怎样显示）**：和 thinklet 的「题型模块」几乎是同一个概念；「只从真题提炼、不预先编」也和「题型的结构由具体题型的 issue 在 design 步骤里定」（0002）一致。
- **判定规则只在服务器上，课堂内容里没有判定规则**：答案和判定规则不进浏览器，这一点和题型怎样设计无关。
- **「对、错、判不了」三种判定，判不了永远不算错；多个解的题按集合判，只说出一部分算错，但给一句下一步**：和题型无关的通用规则。
- **出题手册的教学原则**（结论前后一致、量先于符号、开场当孩子忘了题目、每一幕的开场白能单独听懂、关键时刻必停但不停在答案上、按解法和年级选表示方式、画面只放解题要用的东西）：来自多轮真实的退回，和技术栈无关；「按解法和年级选表示方式」对 3–18 岁同样适用，只是阶梯要往学前和中学延伸。
- **旁白录音工具**（只录缺的和改过的句子，录音清单记文字和声音，测试保证录音和台词一致，换声音只改配置）：和声音引擎无关；录音可以放对象存储（0006）。
- **带标签的背景图库**（年龄段、留给道具的空地的坐标、场景、适合的题型；不合适时生成**通用**的新图入库）：背景是和题型无关的资源，题目引用它的 id。
- **逐句讲述的行为规则**（讲完才进下一幕，一句放不出来就停下等重听，静音时照样按时间推进）：POC 修过 bug 后沉淀下来的，和框架无关。
- **家长预览**（走完整节课，作答点选，服务器照样判，什么都不记录）：和「家长从公共书架挑书分派」相符。

### 教学和内容：部分借鉴

- **只存结果、不存孩子的原话；「独立完成、提示后完成、还没完成」三种结果；做到过一次就算做到**：只存结果符合 thinklet 对孩子信息的要求；但 thinklet 首版不做提示，「提示后完成」这一种暂时用不上。
- **分镜每帧七项、19 项的自查表、冷启动视频审查**：七项的格式和「失败或待验证不能标成通过」可取；19 项太重，POC 自己也大多没填完。
- **题目定义检查**（台词和录音一致、道具在空地里、结论的出现顺序、画面快照只用声明过的词）：检查的内容可取；但在 POC 里是对代码的单元测试。如果内容存成数据，对应的就是发布内容时的校验。
- **结论板、推导板加必停推进**：作为某些题型的部件可取（等量替换和计数类、行程和方程类）；不是平台的通用部件。
- **题目版本**（进度绑在版本上，新版本不动旧进度，打开时问要不要试）：思路可取；孩子侧的提示和家长侧的显示，POC 自己也只写了设计。
- **书 = 年级 + 科目 + 分类，书不删除、只标不可用**：「书不删、标不可用」可取；用第三方品牌名做分类不可取。
- **由 AI 代理从 PDF 批量出题**（先读完整份材料，整体提取公共题型，再逐题确认）：三个阶段的思路可取；但产出是代码 PR，每道题要多轮人工确认，规模上不去。
- **有声的审查视频**：对有声互动内容的验收有用，但只是辅助工具，「仍然要人看、人听」。

### 教学和内容：不适合

- **每道题一份手写的代码模块，重新部署才上线**：和「题型是模块、题目是内容，加新题型不改平台」相反；每道题 2–3 千行代码，12 天两道。POC 的数轴追及用三张表驱动分镜，倒说明一种题型的分镜可以写成数据。
- **答案的文字在公开的 JS 包和静态文件里**：猜到地址就能看到答案。
- **edge-tts 生成旁白**：调用没有公开的接口，没有开发者条款，POC 自己也没敢定。
- **第三方教辅的题目和品牌名放进公开仓库**：thinklet 的内容只由平台团队制作，仓库也是公开的。
- **老师回答时配讲解动画**（作者写讲解清单，模型挑一段）：spike 测得 76.7%，低于标准；清单的编写量随题目线性增长。
- **用 OpenAI 做 AI 老师和语音转写**：OpenAI 不对中国大陆提供服务；孩子的数据出境；首版也不做提示。服务器只拿标识、按内容补文字、答对之前不给答案、模型不判对错、判决句事后过滤这些设计本身是可取的，但要等 AI 进了范围、换了大陆能用的服务才有意义。

### 教学和内容：thinklet 已另定

- **课堂内容放在前后端共用的 TypeScript 包里，前端在构建时打包**（0002、0013）：thinklet 的共用包只放接口约定，内容存数据库（0005）和对象存储（0006）。
- **课尾一道作者手写的变化题，在同一节课里做**（brief）：thinklet 是一次教学后做多个练习。「先猜再揭晓」「作答之前不露出答案」「只改一个关键条件」这几条对练习同样成立。
- **AI 老师、提示、星星**（brief）：首版不做分步引导和提示、趣味激励。
- **讲课角色和电影感背景的视觉语言**（0012）：thinklet 用 Angular CDK 加 Tailwind 自己设计。
- **「AI 审查员考卷」**（0023）：thinklet 的 AI 评审只在本机跑；这套考卷在 POC 也一个案例都没有。

## 前端

### 前端：值得借鉴

- **所有回复先按共用的 schema 校验，不合格就当失败**：可以在 Angular 的 HTTP 层按 `packages/contracts` 的 Zod schema 解析回复（0013）。
- **作答幂等**（浏览器生成作答 id，重试原样再发，只认对应的回执；轮冲突时重读）：可以由 Angular 的服务在重试时复用同一个 id，后端用唯一约束去重。
- **dependency-cruiser 的规则**（展示组件不能取数据，题目之间互相隔离，题目只能按需加载，判定规则不进浏览器，分析到 0 个模块也算失败）：工具和 thinklet 相同（0020）。
- **不依赖框架的引擎**（逐句讲述、播放器的失败分类、录音、静音检测、麦克风轮流用、必停推进、拖动、口语数字解析）：都是纯 TypeScript，可以放进 Angular 的服务，用 signals 暴露状态。
- **SVG 世界坐标的拖动**（屏幕变换矩阵换坐标、pointer capture、拖过去或先点再点、方向键推动、道具是 `role=button`）：Angular CDK 的拖放面向 HTML 列表，SVG 场景里要用这种写法，可以做成指令。
- **舞台用容器查询分横竖屏，用 visualViewport 把控件挪到键盘上面**：Tailwind v4 有容器查询的变体。
- **草稿只记到哪一幕，冲突时让孩子选；学习时间的心跳**：家长要看学习进度，这两样都用得上。
- **每个页面都写全加载中、失败、空、没权限等状态，都有 story 和截图**：和 thinklet「每个状态都跑 axe、都截图」（0022 和 `.docs/architecture.md` 的「测试」一节）一致。
- **家长书架的交互**（几个开关各自等回复，成功后就地更新；手机上是底部抽屉）：可以用 CDK 的 Overlay 和 Dialog。
- **授权卡片、导出、删除放在危险区并重新输密码，隐私说明放在做决定的那一步**：对应《个人信息保护法》和《儿童个人信息网络保护规定》要求的家长同意、查阅和删除。
- **自己画的 SVG 图标（24 格、2px 描边）**：不用图标库。
- **让截图稳定的做法**（固定时钟，动画时长设为 0，等字体和图片，强制重画，关掉 LCD 抗锯齿，`deviceScaleFactor: 1`，偶发失败也算失败，普通运行不写基准）：和 0022「只在 Linux 的 Playwright 镜像里生成基准」配套。
- **无障碍的额外检查**（触控不小于 44px，320px 宽不横向滚动，文字放大 200%，减少动态效果以后没有动画，Tab 顺序和跳转链接，结果状态有文字）：thinklet 要求 WCAG 2.1 AA（0001）。
- **包装 `HTMLMediaElement.prototype.play` 核对音频按顺序播完**：有声内容的端到端测试用得上。

### 前端：部分借鉴

- **设计令牌用 CSS 变量，按用途命名，白天和晚上两组**：令牌的思路可取（Tailwind v4 的 `@theme` 就是 CSS 变量，0012）；按时间切主题、按家庭时区算钟点，产品没有要求。
- **发布更新时检查版本，按「有没有正在进行的事」决定自动刷新还是提示；懒加载的块加载失败时提示重新打开**：懒加载的块在发版后可能 404，这个问题 Angular 一样有；但五级优先级的登记表对这个规模太重。
- **自托管标题字体**：自托管适合大陆访问和本站字体的 CSP；构建时按源码里出现的字子集化不适合，书名和题目在数据库里，源码里没有。
- **语音作答和提问**：「确认后才提交、识别失败不算错、说不了话才给替代」三条规则可取；但 thinklet 现在没有语音，Permissions-Policy 关着麦克风（`.docs/design/interfaces.md`），OpenAI 的转写在大陆用不了，POC 自己的转写在测试环境上也从没成功过。

### 前端：不适合

- **进题前预下载整课的录音，下载完才能开始**：大题要等好几 MB。
- **首屏前设主题的内联脚本**：和 thinklet 的 `script-src 'self'`（`.docs/design/interfaces.md`）冲突。
- **叙事式的注释、电影比喻的命名、6 个泛型参数的定义类型**：读之前要先学一套词。
- **截图膨胀到 1,362 张**：大部分是和视口无关的小部件在三个视口各存一份。

### 前端：thinklet 已另定

- **React、React Router、TanStack Query、CSS Modules**（0003、0012）。
- **TypeBox**（0013：Zod）。
- **Oxlint**（0020：ESLint 加 angular-eslint，含模板的无障碍规则，POC 没有这类规则）。
- **Storybook 加 Playwright 截图**（0022：截图放在组件测试里）。
- **浏览器范围只有 Chromium、模拟 iPhone 和 WebKit**（0001、0022：包括 Firefox）。
- **孩子的 KEY、PIN 登录页面**（brief：孩子没有独立账号）。
- **没有 CSP 和 Permissions-Policy**（0028）。

## 后端、数据和安全

### 后端：值得借鉴

- **不透明的会话令牌**（32 个随机字节，只存 SHA-256，`__Host-` 加 Secure、HttpOnly、SameSite=Lax 的 cookie；凭据版本加家庭世代一次让全家的会话失效；期限在 SQL 里用数据库时间判）：全是普通的表和事务，和 Neon 的连接池（0011）兼容。
- **写请求的防护**（准确的 Origin、自定义请求头、只收 JSON；有会话的写请求再要由会话令牌 HMAC 出来的 CSRF 令牌，定长比较）：可以做成 NestJS 的全局 guard。POC 里哪些 GET 要 CSRF 不统一，这一点不可取。
- **Argon2id，未知账号也算一次假哈希，同一个错误文案**：参数和做法都通用；`argon2` 是原生扩展，能不能在 Vercel 的 Node 26 上打包没有核实。
- **敏感操作要 5 分钟内重新输过密码，写入前用数据库时间再查一次**。
- **注册和找回密码不暴露邮箱是否存在**：同一个回答，同样算哈希。（找回密码「固定等 20 秒」不可取，见下文。）
- **发信意图表**（每个家长每种用途一条，状态机，令牌密文暂存、发完就删，发信结果分五类，「未知」不盲目重试，链接的令牌放在地址的 `#` 后面）：和邮件服务商无关。
- **幂等写入**（浏览器生成的 id 加带密钥的内容指纹加唯一约束；草稿用修订号做乐观并发；每个孩子每道题一把事务级的 advisory lock）：事务级的锁和 PgBouncer 的事务模式兼容。
- **家庭时区和学习时长的算法**（IANA 名，按本地午夜切分，处理夏令时；超过 90 秒的心跳间隔不算，锁住孩子的时钟行）：家长看进度时用得上。日期函数是逻辑，按 0002（和 0016）不能放 `packages/contracts`。
- **响应也按 schema 输出，多余的字段被丢掉**：可以在 NestJS 里用一个拦截器按 Zod schema 解析响应。
- **请求日志只记路由模式、状态、耗时、结果分类，数据库错误只记允许列表里的错误码，每个回答带请求 id**：和 nestjs-pino 的遮挡列表（0014）配套，多一层「默认不记」。
- **就绪检查核对「本版本最后一个迁移已执行」**：比只查数据库连通多一层保证。
- **家庭导出**（包含和不包含的清单写进接口约定、随文件导出、页面先展示；一个事务里读完，不落盘）：符合《个人信息保护法》的查阅、复制权。
- **删除用根上的一行加外键级联；要保留的统计数据在删除时置空关联**。
- **外部服务的授权按用途和政策版本记录，改了披露就升版本、旧授权失效，每次调用前在事务里核对**：和「处理孩子的个人信息需要家长同意」相符。
- **集成测试连真实数据库，专测并发、竞态、跨实例、部分失败、不泄露**：工具已经定了 Testcontainers（0022），POC 的用例可以当写法的样板。

### 后端：部分借鉴

- **限流计数放在 PostgreSQL，桶名用 HMAC 伪名，不存原始的邮箱和 IP**：存储方式可取；但 POC 现在的规则（成功也计数、全站共用上限、没配可信代理）能让一个人挡住所有人。POC 自己已经决定改成只计失败、去掉全站上限。
- **服务开关、独立的删除清单库、加密备份、恢复后重放删除**：「恢复旧备份后不让已删的家庭回来」「恢复演练要计时、核对行数和校验和、恢复出的库默认关闭」可取；但 thinklet 的 staging 只放测试数据（0007），这一套对现在的规模过重；生产环境用哪家云还没定（0008）。备份放在公开仓库的 artifact 里不可取。

### 后端：不适合

- **会话级 advisory lock 做跨实例的槽，进程内计数做并发限制**：thinklet 的测试环境连 Neon 的连接池地址（0011），PgBouncer 的事务模式下会话级的锁会落到别人的会话上；Vercel 函数里进程内的计数也没有意义。
- **找回密码固定等 20 秒**：每个请求占一个函数 20 秒，可以被刷。
- **个人 Gmail 加应用专用密码**：thinklet 的用户以中国大陆为主（brief），家长的邮箱经境外服务处理涉及数据出境，国内投递也没有保证；POC 自己也没核实过 Gmail 的条款和额度。
- **孩子昵称明文存储**：thinklet 要求孩子的个人信息加密保存（架构的安全指标）。
- **所有非 4xx 都回答 503，框架的校验失败都是同一句文案**：程序缺陷和真正的不可用分不开。
- **家长的每个请求（包括只读的）都对家庭行加排他锁**。
- **行级安全加撤销托管商的匿名角色**：只对开了数据 API 的托管商有用。

### 后端：thinklet 已另定

- **Fastify、TypeBox、手写的配置检查、20 个装配文件**（0004、0013、0015、0016）：thinklet 的配置在启动时全部校验，缺了就拒绝启动。
- **孩子用 KEY 自己注册，家庭码加昵称加六位 PIN 登录，180 天的持久会话**（brief）：孩子没有独立账号，也不自己注册。
- **OpenAI 的提示和转写、AI 用量账本**（brief）：首版不做提示。
- **没有安全响应头**（0028）。
- **测试用 PostgreSQL 17、线上 18**（0005：开发和测试用和 Neon 一样的主版本）。
- **一个 Vercel 项目同时发前后端**（0007：两个 Vercel 项目）。

## 检查、交付和流程

### 交付：值得借鉴

- **架构检查分析到 0 个模块时判失败**：dependency-cruiser 在新版 TypeScript 下会「0 个模块、0 个违规」地静默通过；thinklet 用同一个工具（0020）。
- **工具链自检**（故意违规的夹具必须让 lint 和架构检查失败）：确认检查本身没有失效。
- **截图依赖装在按锁文件哈希命名的 Docker 卷里，只拷回基准**：和 0022 的 Linux 镜像配套。
- **先发候选部署，对候选地址冒烟，确认 `main` 没变，再切正式地址；失败时删候选、不动正式地址**：冒烟失败时正式地址不受影响。POC 为此关掉了部署保护，这一点不可取。
- **部署和页面都带发布的提交号，冒烟核对它**：能发现旧版本还在服务。
- **连接数据库前核对主机等于一个变量**：防止一个环境的流程动到别的库。
- **发布前按后端自己的规则检查运行时配置**：配置错误在发布时失败，而不是第一个请求时。
- **「改了哪些目录 → 要跑哪些端到端用例」的对应表**：让「本机只跑受影响的端到端」（0022）的判断可以重复。
- **PR 模板里的「怎么撤回」**。

### 交付：部分借鉴

- **告警开 GitHub issue 指派给值班的人，恢复后自动关；告警演练**：「演练一次，确认能收到通知」可取；多来源、多队列的实现对这个规模太重，底层的定时任务又不可靠。
- **依赖漏洞的分法**（PR 只拦运行时依赖的高危，完整的扫描每周跑，每条公告开一个 issue）：新公告不会让无关的 PR 失败；代价是旧依赖的新漏洞要靠另外的流程去修。thinklet 现在的做法见 0020。
- **每个 issue 一份验收记录**：「实际在测试环境上验证了什么、什么还没验证」可取；把截图提交进仓库不可取。
- **用真实的漏审 bug 检验 AI 审查员**：思路可取，但 POC 一个案例都没有，价值没有证实。
- **风险分级**：规则从目标分支读、新提交撤掉批准，这些可取；但 73% 的 PR 是高风险，人工批准就容易变成走过场。

### 交付：不适合

- **用默认令牌打开自动合并，再写一条 `workflow_run` 加轮询加派发的发布触发链**：复杂，常遇到偶发错误。
- **GitHub 的定时任务做每小时的维护、健康探测、每天的备份**：每小时的维护每天只跑 3–5 次，每小时两次的探测每天只跑 2–5 次，每天的备份比设定的时间晚 3.5–7 小时。
- **批准标签由代理用维护者的令牌自己加**：最快 28 秒批准了 2,500 行，人工关卡名存实亡。
- **1,362 张截图基准和文档截图都进 Git**：仓库到 1 GB。
- **端到端在 CI 里自动重试一次**：会掩盖不稳定的测试。
- **一个 CI 任务串行跑 36 分钟，合并后再跑一遍**。
- **分支规则要求分支最新，却没打开「更新分支」按钮**：PR 会卡住。
- **把 issue 的内容复制一份到路线图文档**：双份维护。
- **项目规则里写这台机器的硬件和 Windows 的限制**：项目规则应该通用。

### 交付：thinklet 已另定

- **自己写 Vercel 的 REST 客户端**（0017：固定版本的 `vercel` 命令行）。
- **CI 里跑 AI 评审**（0023：只在本机跑；POC 配好了却从没开过，也印证了这一点）。
- **风险关卡和批准标签**（0024、0026：合并前用 `origin/main` 的脚本重算等级，核对标签的时间）。
- **Actions 用大版本标签，没有 actionlint、zizmor、CodeQL、gitleaks**（0020、0025）。
- **自己写的提交信息检查，Claude Code 的格式化钩子**（0020 commitlint，0021 lefthook）。
- **`staging` 环境没有保护，密钥放在仓库级**（`.docs/architecture.md` 的平台设置一节、0027）。
- **typescript-eslint 跟不上 TypeScript 7，换成 Oxlint**（0020）：升 TypeScript 大版本前，typescript-eslint、angular-eslint 和 dependency-cruiser 支持的范围同样是限制；Renovate 的大版本升级要手动勾选（0025）。
- **只有 staging，生产只有计划**（0008：同样先只做 staging）。POC 的「自有服务器的退路」和「大陆真机测试」一直排在后面没做。
