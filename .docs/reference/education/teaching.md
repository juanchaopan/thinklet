# POC 的教学方法、题目内容和出题流程

## 概况

POC 的做法是「每道题一部手工编排的有声互动短片」。一道题有 9–18 幕分镜、16–67 句预录旁白、专属的 SVG 道具和分镜规则，代码 2,300–3,300 行（含测试）。另有一套公共的课堂部件（网页上约 9,200 行，不含测试），和一本约 84 KB 的出题手册。

教学设计非常细，但 12 天只上线了两道题，第三道一直没做；没有一道题经过真实孩子的验证，自查表大多填着「待验证」。

## 题目和课堂怎样建模

| 层               | 内容                                                                                                                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 书               | 年级 + 科目 + 分类，例如「一年级 / 数学 / 学而思」。年级一到六年级，科目有数学、语文、英语。书有状态（可用、暂时不可用），永不删除                                                                                       |
| 题目插件         | 只在服务器上：题目摘要（id、版本、标题、所属的书、顺序），判定规则，按顺序的提示，变化题的判定和提示，每一幕给 AI 老师看的说明                                                                                           |
| 课堂内容         | 网站和服务器都读：课堂流程、背景图、语音识别要认的词、幕的顺序、作答那一幕、变化题的声明、每句旁白和它在哪一幕、每一幕的说明和开场白、每一幕得出的结论、画面上各样东西的标识和描述（孩子提问时用）                       |
| 网页上的题目定义 | 代码：片名、讲课角色和站位、道具的范围、配好录音的台词稿、分镜规则（状态机）、画面快照、能拿起的道具、作答（问题、单位、可点的数字、常见错数的说明）、结论板上的图、题目自己的 SVG 场景（见 [frontend.md](frontend.md)） |
| 登记             | 每道题一行，按需加载；加一道题要重新部署                                                                                                                                                                                 |

要点：

- 答案和提示只在服务器的插件里。课堂内容里没有判定规则，所以网站能加载它。
- 每一幕的内容只声明一次。结论板、AI 老师的提问材料和自查都读同一份，出题的人不用在每一幕重复写前面的内容。
- 题目有版本号。孩子的进度绑在版本上，题目出新版本不动旧的进度。

### 结论

每条结论写明：读屏用的一句话；几份一样多的量，例如「1 棵青菜 = 3 组、每组 3 根黄瓜」；第一次出现在哪一幕；后面哪几幕用到它，用到时高亮；用到它的提示；答对以后补上的一句；变化题的「假如」。有自动检查找出结论板画不出来的量，例如不是正整数，或者一件件画超过 8 件却没写成「k×」。

### 判定

- 一个整数的题：整数并且等于答案就对，别的整数是错，不是整数一律「判不了」。
- 几个解的题：按集合判，顺序和重复不计，少一个、多一个都算错。
- 变化题的理由：去掉「嗯、啊」以后不到两个字算「判不了」；其余交给题目自己的规则（正则）；点选时正好选对「没变的」和「变了的」才算对。
- 判定得出「对、错、判不了」三种，服务器再看这一轮有没有用过帮助，换成学习记录的四种结果（规则见 [product.md](product.md) 的「学习记录」）。
- 模型从不判对错。最终答案、变化题的猜数和理由，只由作者的规则判。

## 两道真实的题

| 项目     | 菜园天平「一棵青菜有多重」                                                             | 数轴追及「两车的中点什么时候相距 4 格」                                                                 |
| -------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 来源     | 学而思一年级试卷第 7 题                                                                | 学而思六年级讲义                                                                                        |
| 题意     | 2 棵青菜和 6 个苹果一样重，1 个苹果和 3 根黄瓜一样重，1 棵青菜和几根黄瓜一样重（9 根） | 黄车中点在 −1，蓝车中点在 9，每秒 2 格和 1 格同向走，几秒后相距 4 格（6 秒和 14 秒，即 \|10 − t\| = 4） |
| 流程     | 逐幕探究                                                                               | 列式求解                                                                                                |
| 幕数     | 9（含变化题 4 幕）                                                                     | 18（含核对 2 幕、变化题 2 幕）                                                                          |
| 旁白     | 16 句                                                                                  | 67 句，整节课约 10 分钟                                                                                 |
| 作答     | 说一个整数                                                                             | 一次说出两个数，按集合判                                                                                |
| 变化题   | 每个苹果只换 2 根黄瓜：先猜（6）→ 动手换 → 说理由 → 揭晓，猜数和理由都记录             | 黄车每秒 3 格：只请孩子心里猜，推车核对后揭晓，不记录                                                   |
| 提示     | 2 条，变化题 1 条；常见错数 3 和 6 各有一句说明                                        | 2 条（蓝车在前、黄车在前）；只说 6 或只说 14、说 4、说 10 各有一句                                      |
| 讲课角色 | 小兔，背景是早晨的菜园                                                                 | 猫头鹰博士，背景是黄昏的铁路工坊                                                                        |
| 代码量   | 约 2,290 行（含测试）                                                                  | 约 3,260 行（含测试）                                                                                   |

菜园天平的分镜：开场 → 把一棵青菜拖进篮子 → 苹果一边沉下去，一个个拿走苹果，直到天平回到中间（结论板第一条：1 棵青菜 = 3 个苹果）→ 碰一碰苹果，看到三根黄瓜（第二条：1 个苹果 = 3 根黄瓜）→ 把苹果一个个换成一组黄瓜，天平一直平（第三条：1 棵青菜 = 3 组、每组 3 根黄瓜）→ 作答：孩子开口说「九根」，页面问「我听到你说『九根』，是 9 吗？」，确认后提交 → 变化题。说 3 时提示「这是一个苹果换的根数」，说 6 时提示「这是一开始苹果的个数」。

## 课堂流程

「课堂流程」是讲法上面的一层。每种流程写清六件事：课怎样往下走；最后交什么、怎么判；变化题怎么做；记录哪些证据；学习摘要里怎样显示；自查时按流程核对哪几项。

规则：

- 流程不按学科或年级对应，每道题由维护者选。
- 流程只从真题里提炼，不预先编。没有合适的流程时，先提议新流程（写清六件事并附分镜），维护者确认后才加入清单。
- 新流程必须同时定下学习摘要里怎样显示，否则类型检查不通过。

| 流程     | 适合                                                       | 作答             |
| -------- | ---------------------------------------------------------- | ---------------- |
| 逐幕探究 | 一幕一幕动手发现几个小结论，最后回答一个简短的问题         | 一个整数         |
| 列式求解 | 推着同一组对象经过关键时刻，一步步列出方程，再说出全部的解 | 几个数，按集合判 |

## 一节课怎样上

### 逐幕探究

1. 片名卡，点「开始短片」（同时请求全屏、解锁声音、开始计时）；有草稿时是「接着上次的地方」或「从头做」。
2. 开场慢慢把孩子带进情境，题目的问题讲到以后一直留在画面上。
3. 一幕一幕动手：每幕的开场白先说现在在哪一步、在找什么；孩子拖、点、推道具，对象用平衡、变化等给出反馈；每幕得出一条小结论，留在结论板上；最后一句旁白讲完才进下一幕；每到一幕保存草稿。
4. 作答：旁白讲完响一声，麦克风自己打开（安静约 1.5 秒算说完，最长 30 秒）；页面念出听到的数，孩子确认后才提交；听不出唯一的数时请孩子再说一次，不算错。答错时说作者为这个错数写的那句话，提示按顺序给。
5. 答对以后才进变化题：先猜一个数（显示「记下了 6 根」，不说对错，约 1.5 秒后自动往下）→ 动手（旁白不说结果）→ 说理由（「和你猜的一样吗？说说为什么。」；说不了话或连续两次判不出时，换成「没变的是」「变了的是」两排点选）→ 揭晓，结论板在「假如」后面接上「那么」。猜的那一幕没有提示，因为猜要的是第一反应。

### 列式求解

和逐幕探究的不同：同一组对象从开场留到最后，不换画面；每一幕孩子把对象推到「必停点」，拖得再快也停在那里，停点不落在解上；式子一步步长在推导板上；分情况时每种情况一行，但不写出解；作答一次说出全部的解，只说出一部分算错，并提示「还有哪种情况没找」；答对后回到起点再推一遍，在每个解上停下核对。

### 孩子怎样参与

- 触摸和鼠标：把道具拖到目标上，或者先点道具再点目标；推着道具沿轨道走；式子里的项从画面里点出来。命中范围覆盖整个物体，键盘也能操作，开了「减少动态效果」时一步到位。
- 开口作答：作答和变化题自动开麦；说不了话时才给数字或理由的点选。
- 问老师：每一幕都能按住话筒说话，松开后转成文字，孩子可以改，点「发给小兔」才发；老师的回答只有一句文字（不超过 60 字），不判对错，不在画面上圈位置。同一时间只有一个麦克风开着。
- 家长预览：没有话筒、提问和草稿，作答用点选，服务器照样判，什么都不记录。

## 出题手册的教学原则

这些原则来自维护者多轮退回分镜，和技术栈无关。

### 适用于所有题

- **保留前面得出的结论**：用到时高亮，能指回它从哪来。变化题是另一道题，进入后收起原题的结论，只留「假如」。
- **结论前后一致**：同一样东西只用一张图、一个叫法、一个量词；新的单位只在引入它的那一幕出现；结论板、旁白、字幕、读屏和给老师的材料说同一件事；结论板能画就画，不写数字和汉字。
- **按解法和年级选表示方式**：实物和操作 → 图示、分组、数轴 → 算式 → 方程和不等式；其他学科也有对应的阶梯。用词按年级来：六年级不从一数到十；「绝对值」先摆出它要解决的问题，再给名字。

### 每一幕怎样讲

1. 画面只放解题要用的东西。为了「完整」把无关的东西加回来（例如一条数轴），是最常见的退回原因。
2. 开场当孩子已经忘了题目；不只在第一次讲清题目。
3. 每次回到课堂先接上：每一幕的开场白都要能单独听懂。
4. 每一步接上一步，一幕只推进一件事，每幕结尾留一个问题引出下一步；不要讲得太快。
5. 量先于符号。
6. 式子里的项从画面里点出来，不让孩子拖数字和运算符去拼式子。
7. 算出来的和看出来的对不上时，先把矛盾摆出来。
8. 旁白完整，用温和的口语，同一句话不连说两遍。
9. 关键时刻必停，但不停在答案上；作答之前，画面和旁白都不露出答案。多个解的题不能只认一个解。
10. 画面里的东西是动的；同一样东西前后不换样子。
11. 控件全站一套。
12. 讲解和年级相称，不太浅也不太难：没学过的词先摆出问题再起名，一眼看得出的不逐个数。
13. 题目自己的画留在题目里，不进公共部件。

### 分镜和自查

- 分镜每一帧写七项：画面上有什么、为什么有；孩子做什么（包括做错、做得太快、不做）；旁白全文；动画（包括减少动态效果时）；怎样接上一步、引出下一步；留下的结论；回来时先说的话。每帧配一张图。
- 自查表有 19 项，每项填「通过、失败、待验证」和证据；失败或待验证的不能标成通过。
- 冷启动审查：在真实浏览器的干净会话里，只用孩子能看到和听到的东西，录下连续有声的画面，另外试快拖、慢拖、乱点、停住、重听；回放时按时间戳记下问题。代理模拟只能发现导航和教学上的断点，孩子能否独立理解要单独标记。

## 出题流程

### 从一份 PDF 到上线

1. 先问 PDF 放进哪本书（年级、科目、分类）；新书再问封面；新科目先画科目图标。
2. 读完全部题目，每道题拆出步骤，列出教学需要和候选的流程，这一步不问维护者。
3. 整份 PDF 一起提取公共的流程和部件，新的流程或部件附原型，请维护者确认。
4. 逐题先确认流程，再给 2–3 种讲法（分几幕、用哪些部件、结论怎样留、表示方式、变化题、背景建议），推荐其中一种，维护者确认后才做。
5. 实现后：录旁白，录有声的审查视频，按目标年龄做冷启动审查，逐项填自查表。

这个流程由 AI 代理执行，Claude Code 和 Codex 共用同一本手册。

### 一道题作者要交的东西

原题核对（来源、页码、版本、年龄、标准答案、解法、歧义）；孩子可能怎样想、在哪一步误解，每个典型错误一句可执行的提示；流程、讲法、部件和背景的选择理由；分镜；课堂内容；判定规则和提示；分镜规则（纯函数加单元测试）；SVG 道具和场景（每一幕一个 Storybook story）；画面快照；每句一个录音文件和录音清单；放音检查的端到端测试；审查视频；自查表；验收记录。

### 旁白

- 声音用微软 Edge 的在线朗读（edge-tts，晓晓），语速 −14%，音高 +5Hz。维护者试听过几种本地开源的中文声音，觉得都不如它；合成的机器音被否决（「声音吓人」）；浏览器自带的朗读在 iPhone 上没有声音。
- **条款没解决**：edge-tts 调用的是没有公开、没有开发者条款的接口，生成要发布给孩子的音频是否合规不明确。POC 写明「正式发布前由维护者确认，否则换许可明确的声音」，至今没确认。
- 录音工具的设计和声音无关：只录缺少的和台词改过的句子；每录一句就更新录音清单（每个文件录的是哪句话、什么声音），中断后下次接着录；声音配置变了时停下，要明确要求才全部重录；列出不再用的录音。测试核对每句录音的原文和现在的台词一致。
- 老师对提问的回答没有声音，只有文字。

### 审查视频

一个命令让浏览器从片名卡走到最后一幕，每句旁白放完才做下一步；在页面里录下页面自己发出的声音（旁白和提示音，不录麦克风），同时录画面，用 FFmpeg 合成带声音的视频，另外输出一份媒体事件的时间线。录像「只说明能生成证据，仍然要人看、人听」。

### 图库

- 背景：15 张 16:9 的图，每张带标签（场景、光线、年龄段、留给道具的空地的形状和坐标、裁切时保留的部分、适合的题型、生成用的提示词），另有一句给 AI 老师用的画面描述。挑图的顺序：年龄段 → 空地放不放得下 → 场景和题型。都不合适时生成一张**通用**的新图入库，不为一道题单独画。
- 讲课角色：小兔、松鼠、浣熊、猫头鹰博士，带脸的位置。
- 图由 OpenAI 的图像模型生成。孩子能操作的数学对象都是 SVG。15 张背景里只有 2 张被题目用到。

### 评估

- POC 里叫「evals」的东西是给 AI 代码审查员打分的考卷，不是教学评估，而且一个案例都没有。
- 老师回答的质量只在 spike 里评估过：一次 18 个合成样本、人工检查；一次 30 个合成提问（题内的、跑题的、听不清的、要答案的，调用前写好可以接受的回答），维护者逐条判定。正式规则是「真实模型的核对只用合成问题，经维护者批准后手动跑，不进 CI」。没有自动化的教学质量评估，也没有回归集。

## AI 老师

- 模型：OpenAI 的 GPT-6 Luna，关推理，最多输出 128 个 token，不让 OpenAI 保存，流式返回，10 秒超时，不自动重试。选型的 spike 里 18 个合成样本全部通过，首句的 95 分位延迟 2.46 秒；更大的模型三次泄露了答案，还贵 10 倍。
- 语音转写：浏览器录音 + 服务器调 OpenAI 的转写模型。spike 里 6 条合成普通话全对；浏览器自带的语音识别在 Chrome、Edge、iPhone 上都没出结果。部署后的情况见 [product.md](product.md) 的差距。
- 提问的材料：网页只发标识和数（这一幕现在的画面快照、前面每一幕结束时的快照、最近的关键操作），服务器按课堂内容补上文字：前面每一幕的说明和旁白、这一幕的说明和开场白、已经得出的结论、背景描述。超长时从最早的一幕开始缩短；后面的幕一律不给。
- 提示词的要求：能听懂就直接回答，再给一个下一步，只有完全听不懂才问一个澄清的问题；跑题时用半句亲切地回应，再拉回这一幕；不编材料里没有的东西；不确认也不否认答案；标出提示注入。服务器怎样校验回复，见 [backend.md](backend.md)。
- 老师回答时配画面讲解动画（作者为每一幕写 3–6 段讲解动画，模型挑一段）在 spike 里被否决：挑对 23/30（76.7%，标准是 85%），作答那一幕偏向挑第一项；孩子会问什么无法预料，清单写不全；题目要从 PDF 批量导入时，逐幕写全写对清单做不到。这次 spike 的副产品被保留下来：服务器过滤「对、不对、没错」这类判决句；提示词里写明「直接回答，不要把问题反问给孩子」。
- 学习记录怎样计入提问，见 [product.md](product.md) 的「学习记录」。没有掌握判定，没有题库式的相似题，没有自动生成的变式，也没有间隔复习；再练靠家长按书安排和「值得再练」的列表。

## 内容来源和扩展成本

### 支持的和设想的

| 方面     | 现在支持                       | 设想过                                                                              |
| -------- | ------------------------------ | ----------------------------------------------------------------------------------- |
| 年级     | 一年级、六年级各一本书         | 一到六年级，不限年级                                                                |
| 科目     | 只有数学                       | 语文、英语；手册里有语文阅读、音乐、地理的表示方式举例                              |
| 最终作答 | 一个整数、一组整数             | 选择题、说一句结论、写式子，都还没有部件                                            |
| 画图     | 画板和反馈接口都在，没有题在用 | 愿景里的「说话、画图和逐步反馈」                                                    |
| 对话     | 按住说话，文字回答             | 进题后随时开口、打断讲解、语音回答                                                  |
| 题目数   | 2 道                           | 两份 PDF 的一年级题和六年级讲义都逐题写了场景设计；第三道样例题（彩铅配对）一直没做 |

### 版权

两道题都来自学而思的试卷和讲义。原始 PDF 没进仓库，但题目文字、改编的讲解、旁白和录音都在公开仓库里，书的分类名就是「学而思」。唯一的处理是书的「暂时不可用」状态，没有授权记录，也没有来源和许可的字段。

### 每道题的成本

- **人的时间是主要成本**：维护者要确认流程和 2–3 种讲法、每一帧分镜和画面、试听每句录音、看完有声录像（第二道题约 10 分钟）。原型改了 10 多轮，正式版的分镜又被退回过。
- **代码**：每道题 2,300–3,300 行，全是代码，不是数据。
- **素材**：背景尽量复用图库（新图约 0.04 美元一张）；旁白免费，但要网络和试听；SVG 道具每道题手画。
- **运行**：老师回答约 0.04–0.08 美元每千次（两次 spike 的测量：选型时的短提问约 0.038 美元，后来带上这节课材料的提问约 0.077 美元）；转写约 0.375 美元每千次（每次 5 秒录音）。
- **矛盾**：手册的愿景是 AI 代理从 PDF 批量出题，但每道题仍要写代码、要维护者多轮确认。否决讲解动画的理由正是「批量导入时写不全」，同样的理由也适用于每一幕的分镜和 SVG 场景本身。

## 没做完的和偏离的

1. 第三道样例题没做。
2. 免按键的语音对话、老师用语音回答，都没推进。
3. 第二道题的变化题不记录结果；「列式求解」在学习摘要里怎样显示待定。
4. 画图作答没有题在用。
5. 原型里「孩子自己搭算式」的设想，被手册的第 6 条反转为「不让孩子拖数字拼式子」。
6. 原型设想「理由由模型或人工判断」，正式版改成作者的正则加点选；正则很脆，只认几种说法。
7. 真实孩子的验证为零；「两个代理工具共用一套标准」也从没用同一份 PDF 对照跑过。
8. 题目内容的保护、旁白声音的条款，都没解决。
