# POC 的产品：意图和实现

POC 的需求散在愿景、需求清单、issue 正文和评论里，issue 正文常被后面一条「以这条为准」的评论覆盖。下面写的是维护者最后一次决定的意图，以及实现和它的差距。

## 用户和目标

定位：「为儿童提供中文交互式解题教学，通过说话、画图和逐步反馈培养独立理解，让家长了解孩子的学习进展。」

| 角色       | 需要                                                                                                                                           | 说明                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 孩子       | 友好、耐心、能反复听讲；知道哪一步出了问题、下一步怎么试；自己推出答案                                                                         | 不限年级；现有内容是一年级和六年级。孩子账号没有年级字段，也不填真名         |
| 家长       | 邮箱注册；让孩子加入家庭；按书给孩子安排练习；看每个孩子每天学了多久、每道题的结果；管理 AI 授权；导出和删除家庭数据；重置孩子的 PIN；预览题目 | 一个家庭可以有几个孩子；一个家庭能有几个家长始终没定，实际是一个家长一个家庭 |
| 内容维护者 | 提供真题（PDF），由 AI 代理逐题设计专属的教学页面；在书单里改书的状态和封面                                                                    | 就是维护者本人。没有在线出题后台                                             |
| 老师、学校 | 不是用户                                                                                                                                       | 「老师」只指课堂里的 AI 讲课角色（小兔、猫头鹰博士等）                       |

成功标准：

- 学习目标是孩子在相似题上需要的帮助越来越少，最终能独立解题。完成次数不等于理解；「掌握」的判定规则始终没定。
- 试点规模：最多 10 个家庭、约 3 个孩子同时学习。
- AI 不可用时，课堂仍能靠题目自带的提示继续。
- 性能：普通操作 2 秒内、AI 5 秒内开始有效回应，10 秒没开始就给出引导选项，并且要在中国大陆的真实设备上测。这一条从没测过。

约束：只有简体中文；部署要免费，付费 AI 由维护者允许并默认开启；中国大陆能访问是发布的硬条件；不放演示题，不伪造学习进度；家庭之间数据隔离；家长授权后才把孩子的输入交给外部 AI；默认不保存原始录音和绘图；手机、平板和电脑的常见浏览器都要能用，微信内置浏览器不是必需的。

### 视觉和无障碍

- 两套主题：白天「手作工作台」（暖米色纸纹、森林绿按钮），晚上「暮光剧场」（深墨绿、暖金按钮），按家庭时区的钟点在 6:00 和 18:00 切换。题目页不随主题变。
- 自己画的 SVG 图标，自托管的中文标题字体，界面文字从简（口号和安慰话删掉，隐私和不可撤回的说明放在做决定的那一步）。
- WCAG 2.2 AA、键盘、减少动态效果、触控目标不小于 44px、缩放，都有自动检查。真机上的触摸、读屏和声音没有验证过。

## 页面和主要流程

| 地址                                                   | 页面                                                                                                         | 谁能看           |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ | ---------------- |
| `/`                                                    | 只做跳转：孩子去「我的书」，家长去家长空间，其他人去孩子登录                                                 | 所有人           |
| `/login/child`、`/login/parent`                        | 登录页的两个页签，孩子填家庭码、昵称和 PIN，家长填邮箱和密码                                                 | 没登录的人       |
| `/signup`                                              | 家长注册（「请使用您自己的邮箱，不需要填写孩子的信息」）                                                     | 没登录的人       |
| `/join`                                                | 孩子用 KEY 加入家庭，填昵称（「不用真名」）和 PIN；成功后显示家庭码                                          | 有 KEY 的孩子    |
| `/password/forgot`、`/password/reset`、`/email/verify` | 找回密码、重设密码、验证邮箱                                                                                 | 家长             |
| `/books`                                               | 孩子的「我的书」：筛选、书卡、展开看题                                                                       | 孩子             |
| `/problems/<题目>/<版本>`                              | 全屏的题目页；孩子是做题模式，家长是预览模式；按情况显示「登录后才能打开」「请家长安排这本书」「暂时不可用」 | 孩子、家长       |
| `/family` 及其下的五个部分                             | 家长空间                                                                                                     | 验证过邮箱的家长 |

**家长注册到登录**：注册时同时建一个家庭 → 只有 15 分钟的受限会话，只能看验证状态和退出 → 邮件里的一次性链接验证邮箱（令牌放在链接的 `#` 后面，不进服务器日志）→ 重新登录拿到 7 天的会话。生成 KEY、重置 PIN、导出、删除、改 AI 授权这些敏感操作，要 5 分钟内重新输过密码。

**孩子加入和登录**：家长生成 KEY → 孩子在 `/join` 填 KEY、昵称、PIN，同一个事务里用掉 KEY、建孩子，网络重试不会建出两个孩子 → 成功页显示家庭码 → 孩子用家庭码 + 昵称 + PIN 登录，设备默认记住家庭码和昵称（不记 PIN）。忘了 PIN 由家长重置。一个浏览器同一时间只能有一个会话：孩子登录会替换家长的会话，反过来也一样，家长要预览就得先让孩子退出。

**安排到学习**：家长在书架上点「安排」→ 选孩子 → 孩子的「我的书」出现这本书，带「新」字 → 孩子打开书里任意一道题后，「新」字消失 → 题目页：片名卡 →「开始短片」或「接着上次的地方」→ 全屏 → 一幕一幕动手 → 作答 → 变化题 → 结束。家长取消安排时，书从孩子首页消失，学习记录不清零。

**导出和删除**：导出前页面列出包含什么（家长邮箱、孩子昵称、学习摘要、安排的书和进度、未过期的草稿、AI 授权、变化题结果、每天的学习时长）和不包含什么（密码和 PIN 的哈希、KEY、家庭码、会话、原始录音、逐次作答的内部记录、AI 用量），服务器不留副本。删除前列出删掉的和会留下的（AI 用量记录去掉家庭和孩子的编号后保留、已经发出的邮件、已经下载的导出、已经发给 AI 服务的请求）。

## 业务规则

### 权限

- 服务器从会话确定家庭和孩子，不信任浏览器传来的家庭编号。访问别家的孩子，回答和「孩子不存在」完全一样。
- 一道题能不能打开，按顺序判：题目或版本不存在 → 不存在；孩子并且这本书没安排给他 → 没安排；书暂时不可用 → 不可用；否则孩子是做题模式，家长是预览模式。打开题目的请求只读不写。
- 题目下面的作答、草稿、变化题和 AI 请求，都先经过同一个「孩子 + 题目」的检查。

### 会话和凭据

- 孩子的会话 180 天不活动才过期，每次有效访问顺延；家长空闲 12 小时、最长 7 天；没验证邮箱的家长 15 分钟。
- 家长改密码时全家所有会话失效；家长重置孩子的 PIN 时，这个孩子的所有会话失效。

### 登录限流

| 范围                  | 现在的规则                                | 维护者已决定改成                 |
| --------------------- | ----------------------------------------- | -------------------------------- |
| 孩子（家庭码 + 昵称） | 15 分钟 5 次、24 小时 20 次，成功也计数   | 只计输错，成功后清零             |
| 家长邮箱              | 15 分钟 10 次、24 小时 50 次              | 只计输错；登录和注册、验证分开计 |
| 家庭                  | 15 分钟 50 次、24 小时 200 次             | 不变，只计输错                   |
| 来源 IP               | 15 分钟 30 次、24 小时 200 次             | 孩子和家长分开计                 |
| 全站                  | 15 分钟 100 次、24 小时 500 次            | 去掉，只记一条警告日志           |
| AI 调用               | 每个孩子每分钟 6 次、每个家庭每分钟 18 次 | —                                |

不用验证码，不永久封禁。现在的规则下，一个人乱试就能让全站所有人都登录不了。

### 学习记录

- 一「轮」练习从开始一直到最终答对；答对以后开新的一轮。
- 最终作答的结果：独立完成、提示后完成、答错、判不了。判不了不算错。用过作者写的提示、或在作答那一幕问过老师，再答对，就是提示后完成。
- 多个解的题按集合判，只说出一部分算错，不设「部分对」。
- 变化题：猜的数记独立答对、提示后答对或答错；理由只分说清了和没说清；判不了的不记。只存结果，不存孩子的原话、转写文字或它们的哈希。
- 书的进度：书里每道题在任何版本上答对过，就算做过。
- 家长看到的数字只说做了多少，不说是否掌握。

### 学习时长

只在题目页可见、孩子最近 2 分钟内动过手时计时。服务器按心跳的间隔算，间隔超过 90 秒的那一段不算。每个孩子每天一个总数，按家庭时区的本地日子切分，跨过午夜的分到两天，夏令时那天也算对。

### 数据保留

| 数据                           | 保留多久                             |
| ------------------------------ | ------------------------------------ |
| 草稿（含绘图笔迹）             | 最后一次编辑后 7 天                  |
| 原始录音                       | 不落盘，只在转写请求的内存里         |
| 学习记录、学习时长、变化题结果 | 到删除家庭为止                       |
| 数据库备份                     | 每天一份，加密，保留 14 天           |
| 删除清单                       | 删除完成后 15 天                     |
| 限流计数                       | 最多 25 小时                         |
| AI 用量记录                    | 永久，删除家庭后去掉家庭和孩子的编号 |

### AI 的规则

- 真正调用外部 AI 要同时满足：总开关开着、后端配了密钥、部署者确认过这项服务能处理孩子数据、家长授权、本月预算有剩、没超过限流。缺一项就不发请求、不产生费用，孩子用题目的提示继续。
- 密钥只在后端。不能用代理或海外部署绕过 AI 服务的地区限制。
- AI 不判对错，对错只由题目规则判。模型的回答里出现肯定或否定孩子说法的句子时，服务器换成一句「请看着画面自己核对」。
- 孩子提问时带的材料只用题目声明过的标识和数，服务器核对后才用；过了作答那一幕的提问，服务器要先查到孩子答对过，才把最终答案交给模型。

## 数据概念

| 概念           | 含义                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 家庭           | 一个家庭码（只用来定位家庭，本身不授予权限）和一个时区；家长和孩子都属于它；也是删除的单位 |
| 家长           | 邮箱、密码哈希、是否验证过邮箱                                                             |
| 孩子           | 昵称（家庭内唯一）、PIN 的哈希；没有年级，没有真名                                         |
| 注册 KEY       | 一次性、24 小时有效、可以撤销，只用于让孩子加入家庭                                        |
| 书             | 年级 + 科目 + 分类；稳定的 id；状态；可选的封面                                            |
| 安排           | 家长把一本书给一个孩子；永久有效；记下孩子第一次打开的时间                                 |
| 题目           | 稳定的 id 加版本号，属于一本书                                                             |
| 课堂流程       | 讲法上面的一层，现有「逐幕探究」和「列式求解」两种（见 [teaching.md](teaching.md)）        |
| 幕             | 一节课里的一个小目标                                                                       |
| 结论           | 每一幕得出的东西，用结论板或推导板留在画面上                                               |
| 变化题         | 只改一个关键条件的另一道题（「假如……那么……」）                                             |
| 轮、作答       | 一次从开始到答对的练习；一次提交，带幂等键                                                 |
| 帮助           | 打开一条提示，或在作答那一幕问老师                                                         |
| 草稿           | 做到哪一幕和绘图笔迹，带版本号，7 天过期                                                   |
| 授权           | 每个家庭每种用途一条：政策版本、是否同意                                                   |
| 删除清单       | 放在另一个数据库里，只存内部的家庭编号和时间，用来在恢复旧备份后再删一遍                   |
| 绘景、讲课角色 | 带标签的共用图库（年龄段、留给道具的空地、场景、光线、适合的题型）                         |

## 隐私和合规

做了的：

- 家长按用途、按政策版本授权外部 AI 处理孩子的输入，可以撤回；页面写明「应用不保存」不等于「服务商不保留」。
- 数据最少：孩子只有昵称和 PIN，没有年龄、年级、真名、照片；家长注册只要自己的邮箱。
- 不保存原始录音；绘图只作为 7 天的草稿；变化题的理由只存结果；日志里没有家庭数据。
- 家庭数据可以导出和删除；删除清单保证从旧备份恢复时，已删除的家庭不会回来。

没做的：

- 没有隐私政策和用户协议，没有「同意本应用收集孩子信息」的单独步骤，只有对外部 AI 的授权。
- 没有考虑《个人信息保护法》对不满 14 周岁孩子的个人信息的要求（属于敏感个人信息，要监护人单独同意），也没有考虑 ICP 备案。
- 没有数据出境评估：测试环境在新加坡，AI 在美国。
- 旁白用的微软在线朗读接口，能不能用来发布给孩子的音频，条款没确认。
- 邮件用维护者的个人 Gmail，用途、额度和条款的核实一直挂在上线门槛上。
- 题目和品牌名取自第三方教辅（学而思），放在公开仓库里，没有授权记录。

## 意图和实现的差距

### 从没验证或没做到的硬目标

1. 从没上过生产，只有一个放合成账号的测试环境。
2. 中国大陆能访问是发布的硬条件，但从没在大陆网络和设备上测过，性能目标也没测过。
3. 三个孩子同时学习没测过。
4. 产品面向大陆的孩子，AI 却用 OpenAI；所有文档都说服务资格必须核实、不能绕过，但一直没有结论。要么换服务，要么 AI 功能对目标用户永远「暂未启用」。
5. 没有真实的孩子用过，孩子能不能独立理解和举一反三没验证；所有「冷启动审查」都是代理模拟的。
6. 「掌握」的判定没定。
7. 平板和手机真机上的全屏、自动开麦、触摸和读屏都没验证；iPhone 上设备朗读没有声音。
8. 测试环境上语音识别每次都「没有听出来」，原因没查明。开口作答和问老师这两条核心交互，在部署的环境里都退回到点数字，问老师则用不了。

### 内容覆盖

- 计划三道样例题，只做了两道；两份 PDF 里其余约 28 组题只有设计说明。
- 第二道题的变化题不记录结果，自查卡多项「待验证」。
- 封面库是空的，只有数学一个科目。

### 规划了但没落地的

- 画图作答是第一版需求，画板和反馈接口都做了，却没有一道题在用。
- 免按键的语音对话、老师用语音回答，都没有 issue。
- 题目文件不受保护，猜到地址就能下载。
- 家长空间里没有预览入口；家长不能查看和撤销设备会话；普通表单在发布更新、页面自动刷新时会丢输入。

### 文档之间、文档和代码之间的矛盾

- 需求清单开头写「以下需求均有效且尚未实现」，而大部分已经实现；README 和状态文档把已经完成的功能列为没完成。
- 主题的决策记录写「按设备本地时间」切换，实际按家庭时区。
- 旁白的声音前后换过（先是本地的 Piper，后来是微软在线朗读），旧的结论没有更新。
- 「列式求解」有没有变化题，手册和维护者的最新说法不一致，至今待定。
- 「分类」原意是题目的主题，实际被用成了来源（学而思），两本书因此同名，只靠年级区分。
- 「提示阶梯」写的是「从小提示到示范的逐级帮助」，实际只有作者写的 1–2 条文字提示，没有示范这一级。

## 方向的变化

12 天里改过的方向：

- **放弃的**：单题安排、安排期限和状态、孩子自由复习、公开题库和访客看短片、老师在画面上配讲解动画、「按住说出答案」的双按钮、AI 看图反馈的面板、按设备时钟切主题、按自然周统计、孩子的年级字段、数据库从 Supabase 换到 Neon。
- **改过的**：付费 AI 从「默认关闭」改成「默认开启」；作答从「按住说话」改成「旁白讲完自动开麦」；学习摘要从「每个版本一行五个次数」改成「每道题一项三种结果」；网站视觉在维护者觉得「太素、像 AI 做的测试应用」之后整体改版。
- **一条反复出现的原则**：每道题按自己的思路设计专属的界面，先分析真题，再从不同题目里提炼共用的部件，不预先做通用的教学组件。
