# 0022 测试

## 背景

每个测试对象都要定工具、什么时候跑、本机跑多少。仓库是公开的，GitHub 标准机器上的 CI 不限分钟数。

## 比较过的方案

| 方面         | 选项                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 单元         | 三个包都用 Vitest；前端 Vitest、后端 Jest                                          |
| 组件         | Vitest 浏览器模式加 Testing Library 和 axe；Vitest 加 jsdom                        |
| 集成         | Vitest 加 supertest 和 Testcontainers；用 Docker Compose 提前起好依赖              |
| 端到端       | Playwright 加 axe；Cypress 加 axe                                                  |
| 自动安全扫描 | ZAP 基线扫描；不加                                                                 |
| 迁移测试     | 写；不写                                                                           |
| 截图对比     | 放在组件测试里，统一在 Linux 上生成；放在端到端测试里                              |
| 覆盖率       | 80% 下限，只算单元和组件测试；只记录                                               |
| 本机范围     | 单元、组件、集成全跑，端到端只跑受影响的；全部全跑；重的都只跑受影响的             |
| 冒烟测试     | 首页加后端健康检查（检查数据库和存储）；首页加只说明后端在运行的健康检查；只查首页 |

## 决定

- 除冒烟测试外，每一项都用第一个选项。
- 契约测试不做：前后端在同一个仓库，一起发布。
- 性能和负载测试不做：没有性能指标。
- 冒烟测试是打了 `@smoke` 标签的 Playwright 测试，现在有四条：
  - 测试环境的首页能正常打开，没有控制台报错，也没有被 CSP 拦下的内容；
  - 经过前端的 `/api` 转发调用 `GET /api/health` 返回 200。这个接口会在数据库上执行 `SELECT 1`，并确认存储桶能访问；
  - 首页带着前端的安全响应头；
  - 经过前端转发的 `/api/health` 带着后端的安全响应头。
  - 四条都只读，都打上 `@production-safe` 标签。
- 指标由哪个测试对象检查、各项什么时候跑，见 `architecture.md` 的“测试”一节。PR CI 时机的每项都是必过检查。

## 理由

- 全仓库只用一种测试写法。
- 组件在真实的浏览器里渲染，布局、焦点、触控和无障碍的检查才准，也才能截图。
- 测试自己起依赖、自己删掉，每次都从干净的状态开始。
- Playwright 一套代码能跑 Chromium、Firefox 和 WebKit，正好覆盖兼容性指标。
- 平台处理儿童信息，安全扫描值得加；家长和孩子的数据丢了代价很大，迁移测试也值得写。
- Windows 和 Linux 的字体渲染不同，截图基准图只在 Linux 上生成，结果才稳定。
- 首页是静态文件，只查首页的话，后端没发布成功、或者连不上数据库和存储，冒烟测试也会通过；加上健康检查，冒烟测试才能确认整条链路是通的。
- 前端的安全响应头写在 CD 生成的 `vercel.json` 里，本机测试用的是模拟 Vercel 的服务器；只有在测试环境上检查，才能确认 Vercel 真的发出了这些头。

## 代价

- 本机跑测试要开着 Docker，截图测试还要用 Playwright 的 Docker 镜像。
- 覆盖率下限偶尔会让人为了凑数字去测意义不大的代码。
- 端到端测试在本机只跑受影响的部分，代理判断漏了的流程要到 CI 才会失败。
- 健康检查每次被调用都会唤醒 Neon 的数据库。
- 仓库改成私有后，每月只有 2000 分钟 CI。

## 何时重新考虑

- 加了性能指标。
- 有团队以外的调用方使用接口。
- 仓库改成私有。
