# 0027 环境变量和密钥

## 背景

测试环境的部署、迁移、冒烟测试和后端运行，都要用到一些地址和凭据。密钥的值任何时候都不能显示在对话里。

## 比较过的方案

- 清单里的 `VERCEL_TOKEN`：由用户生成，存成不提交的文件，由代理从文件读入 GitHub；或者由用户在 GitHub 网页上手动粘贴。

## 决定

- 按 `architecture.md` 的“环境变量和密钥”一节的清单设置。GitHub 上建一个 `staging` 环境，密钥的名称里不带环境。
- `VERCEL_TOKEN` 由用户在 Vercel 网站上生成，存成不提交的文件，由代理从文件读入 GitHub。
- 由建资源产生的值，直接从命令输出写进 GitHub 或 Vercel，从不显示。

## 理由

- 公开仓库能按环境保存密钥，生产环境建好后用它自己的环境，名称不冲突。
- 值不经过对话，也不进入 shell 历史。

## 代价

- 清单里的值分散在 GitHub 和 Vercel 两处。

## 何时重新考虑

- 第一个存孩子个人信息的 issue，要加加密用的密钥。
- 某个测试第一次需要外部账号。
- 建生产环境时。
