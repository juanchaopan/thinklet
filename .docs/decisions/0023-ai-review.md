# 0023 AI 评审和评审标准

## 背景

每个 PR 合并前都要经过 AI 评审。工具检查不了的规则写在 `REVIEW.md` 里，由 AI 评审和人的批准来检查。

## 比较过的方案

- 级别：low；medium；high。
- 运行的地方：只在本机；CI 也跑，用 Claude 订阅的令牌；CI 也跑，用 Anthropic API 密钥。
- `REVIEW.md` 的条目：逐条确认。

## 决定

- 开 PR 前，代理在本机跑 `/code-review`，级别是 medium。评审发现的每个问题都要改掉，或者写明理由才能关掉。CI 里不跑 AI 评审。
- 评审意见用中文。
- `REVIEW.md` 有八条：分层各管各的事；保护孩子的个人信息；接口只有一份定义；不依赖 Vercel 和 Neon 的专有接口；界面照顾孩子和无障碍；测试写在最低能测到的一层；注释只说现在的代码；不写死环境和个人信息。具体内容见 `architecture.md`。

## 理由

- medium 级别在发现问题的数量和可信度之间比较平衡。
- 只在本机跑不用配密钥，也不额外花钱。

## 代价

- 在网页上直接改代码，或者别人提的 PR，都没有 AI 评审。

## 何时重新考虑

- 有其他人开始提 PR。
