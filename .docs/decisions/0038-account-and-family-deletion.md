# 0038 删除家长账号和家庭

## 背景

#14 要让家长能删除自己的账号、管理员能删除家庭，删掉的数据在数据库和对象存储里不留下。家长的账号由 Authing 管：名字、邮箱和密码存在 Authing，本站只存 Authing 给的标识和家长的名字（决策 0029）。Authing 的个人中心不能让用户自己注销账号；管理员在控制台或者用管理 API 删除用户时，Authing 会发一个 `user:deleted` webhook，请求头里带着配置时填的密钥，没有签名，文档没写失败后会不会重发。对象存储里现在只有封面，没有家长和孩子的数据。

## 比较过的方案

- Authing 上的账号：只删本站的数据，Authing 的账号留着；先删 Authing 的账号，成功了再删本站的。
- 本站什么时候删：后端调管理 API，Authing 返回成功后在同一个请求里删；等 Authing 的 `user:deleted` webhook 来了再删；两种都做；家长申请、平台团队在控制台里删，再等 webhook。
- 调管理 API：Node 自带的 fetch；Authing 官方的 Node SDK。
- 怎么删：当场在一个事务里真删；先标记待删，冷静期过后由定时任务真删。
- 谁能删家庭：只有管理员，随时能删；只有管理员，且家里只剩他一位家长；管理员发起、其他家长都同意。
- 家长删除账号的条件：按他在每个家庭的情况处理；先离开或删掉所有家庭；不是任何家庭的管理员就能删。
- 控制台里直接删掉的管理员：管理员交给最早加入的家长；他做管理员的家庭跟着删掉。
- 开发机和测试里的 Authing 管理 API 和 webhook：仓库里写一个小的替身服务；测试里用 msw 拦截，开发机不支持。

## 决定

- 家长删除账号时，后端先用用户池编号和密钥换管理令牌，再用管理 API 删除这个 Authing 用户；请求用 Node 自带的 fetch，接入放在 `apps/api/src/infrastructure/`。
- Authing 返回成功后，在同一个请求里用一个事务删掉这位家长在本站的数据，并清掉他的登录；Authing 返回失败就什么都不删。
- 后端也收 webhook：`POST /api/webhooks/authing` 不要登录、不查 `Origin`，用定长比较核对请求头里的 webhook 密钥；收到 `user:deleted` 后，按配置的 issuer 和用户的标识找到家长，在一个事务里删掉这位家长在本站的数据。找不到的用户（家长自己删的已经删过了）不处理，同一个通知来两次结果一样。在 Authing 控制台里删掉的用户靠它同步。
- 家长只有不是任何家庭的管理员时才能删除自己的账号：先把管理员设给别人，或者删掉只剩他的家庭。删掉时，他在各个家庭的成员关系和他发的加入申请一起删掉。
- 在 Authing 控制台里直接删掉、绕过了这个条件的家长：他是管理员、家里还有别的家长的家庭，管理员交给其余家长里最早加入的一位；只剩他一位家长的家庭整个删掉。
- 只有管理员能删除家庭，家里还有别的家长时也能删。在一个事务里当场删掉：家庭里的孩子（连同记住的设备、扫码登录链接、分派的书和以后的学习记录）、家庭获取的书、加入申请和所有家长在这个家庭的成员关系；家长的账号留着。
- 都是真删，不留待删标记，也没有冷静期；能不能反悔只靠删除前的确认。审计表里的记录不删（决策 0040），只剩编号。
- 新的环境变量：`AUTHING_MANAGEMENT_ORIGIN`、`AUTHING_USER_POOL_ID`（变量），`AUTHING_USER_POOL_SECRET`、`AUTHING_WEBHOOK_SECRET`（密钥）。webhook 密钥由代理随机生成，用户从不提交的文件复制进 Authing 控制台。
- 开发机和测试里用仓库里的替身服务（`apps/api/test/support/`）代替 Authing：它实现换管理令牌和删除用户两个接口，删除后带着 webhook 密钥回调后端。集成和端到端测试自己起它、测完关掉，`task dev` 也起它。真的 Authing 只在测试环境上手工试一次。

## 理由

- 账号本来就由 Authing 管，删账号就要删掉 Authing 那边存的名字、邮箱和密码，本站只留着标识没有意义。
- 用户希望 Authing 删成功之后再删本站的数据。管理 API 当场就告诉后端删没删成，家长自己删时马上删本站的数据，不怕 webhook 丢；再收 webhook，平台团队在控制台里手工删的用户也会同步。
- 只用到两个接口，自己用 fetch 写，不加依赖，测试里换成替身服务也简单。
- 管理员要对家庭负责，删家庭和交出管理员都由他做；先交出管理员才能删账号，家庭不会因为一个人注销就没了管理员。控制台里的删除绕过了这一步，自动交给最早加入的家长，家庭和孩子都保住。
- 真删在一个事务里就做完，不用定时任务，查询也不用处处排除待删的数据；家长的 Authing 账号已经删了，冷静期里也登录不回来。
- 替身服务让集成和端到端测试走完整的流程，开发机上也能试删除。

## 代价

- 后端拿着用户池密钥，它能管整个用户池，泄漏了影响所有家长的账号。
- 删除账号只在 Authing 上做得到：换身份服务时，管理 API 的接入和 webhook 都要重写，`AUTHING_*` 也跟着换。
- webhook 只靠一个共享密钥证明来源，没有签名，也防不了重放；密钥泄漏了，别人能伪造删除通知。
- 控制台里删掉的用户，通知没送到时，本站的数据留着，Authing 那边的账号已经没了；Authing 的文档没写会不会重发。
- Authing 删成功、本站的事务却失败时，家长的 Authing 账号已经没了，本站的数据要等 webhook 来删。
- 删掉的数据在 Neon 的历史记录里还会留一段时间。
- 管理员能一个人删掉整个家庭，其他家长的孩子数据也一起没了，不能恢复。
- 替身服务要靠测试保证它和 Authing 的文档一致，Authing 改了接口时它不会跟着变。

## 何时重新考虑

- webhook 丢通知，本站留下了删不掉的数据。
- 换身份服务，或者建生产环境。
- Authing 支持用户自己注销账号，或者 webhook 加了签名。
