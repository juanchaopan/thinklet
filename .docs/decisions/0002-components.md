# 0002 组件

## 背景

要确定项目由哪些能单独启动的部分组成。简介要求一套自适应网页，内容以书本组织，还会有图片、音频这类文件。家长要开放注册，能用邮箱、Google 等方式登录和找回密码。

## 比较过的方案

- 前端：Angular、React、Vue。
- 后端语言：TypeScript（Node.js）、Kotlin（JVM）、Java（JVM）。
- 数据库：PostgreSQL、MySQL。
- 对象存储：现在就加；等第一个用到文件的 issue 再加。
- 共用代码：起初设想把题型模块做成前后端共用。用户指出题型还没有设计，而且共用包会在浏览器和服务器两边各跑一份，一般只用于接口约定。于是改为共用包只放接口约定。
- 家长的账号：用第三方身份服务 Authing；本站自己存账号和密码。

## 决定

- `apps/web`：Angular 前端。
- `apps/api`：TypeScript 写的 Node.js 后端。
- `packages/contracts`：只放接口约定（Zod schema 和类型）的共用包。内容文件的格式也是接口约定，放在这里。
- PostgreSQL 数据库。
- 兼容 S3 的对象存储，现在就加。
- 第三方身份服务 Authing：管家长的注册、登录、找回密码和社交登录，本站只通过 OIDC 标准协议接入（见决策 0029）。
- 题型由前端的组件、内容文件里的流程和题目组成（决策 0041），不另设能单独启动的部分。

## 理由

- 团队熟悉 Angular。
- 前后端用同一种语言，接口约定写一次就能两边共用。Node.js 占用的内存少，适合小服务器。POC 也是 TypeScript 写的，分析时更容易复用。
- PostgreSQL 的 JSONB 适合存不同结构的内容，事务能保证写入后立刻可见。
- 用户决定现在就加对象存储。
- 找回密码要发邮件，社交登录要对接各平台；交给身份服务，本站不经手家长的密码，也不用自己发邮件。
- 判分只在后端做（决策 0044），播放只在前端做，两边共用的只有内容文件的格式，共用包只放接口约定仍然够用。

## 代价

- 团队也熟悉 Kotlin 和 Java，选了 TypeScript 就用不上这部分经验。
- 家长登录依赖一个外部服务。

## 何时重新考虑

- 发现确实有需要前后端共用的题型逻辑。
- 后端出现 Node.js 不擅长的负载，比如大量计算。
