# 0013 接口约定

## 背景

前后端之间的请求和响应格式要有一份定义，前端推类型，后端做校验。

## 比较过的方案

- 共用包里的 Zod schema。
- OpenAPI：由后端的装饰器生成文档，前端再从文档生成客户端。
- class-validator（NestJS 默认）：用带装饰器的类来校验。

## 决定

接口约定写在 `packages/contracts` 的 Zod schema 里。后端用它校验请求，前端用它推出类型。前后端都不手写重复的类型。

## 理由

- 定义只有一份，不需要代码生成。
- 后端的配置校验也用 Zod（0015），全仓库只用一个校验库。

## 代价

- 没有现成的接口文档。
- 共用包同时被浏览器端的 Angular 和服务器端的 NestJS 引用，构建出来的模块格式要两边都能用。

## 何时重新考虑

- 有团队以外的调用方要用这些接口，需要正式的接口文档。
