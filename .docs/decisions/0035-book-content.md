# 0035 书本数据和导入

## 背景

#9 的书库要一批书本：书名、简介、封面、学科和年级。内容只由平台团队制作，暂时没有管理后台。测试环境、开发机和测试都要能重复导入同一份数据。

## 比较过的方案

- 格式：JSON；YAML（要加解析库）。
- 年级：写在代码里；和学科一样放一个数据文件。
- 封面图：固定文件名 `cover.webp` 或 `cover.png`，限定大小和比例，不自动缩图；放任意大小的原图，导入时用 sharp 缩成统一尺寸。
- 导入命令：后端里用 NestJS 应用上下文启动的命令；`tools/` 下的独立脚本。
- 示例书：就放在 `content/` 里；另放一个只给测试环境和开发机导入的文件夹。

## 决定

- 书本数据放在仓库根目录的 `content/` 里，都用 JSON：`grades.json`、`subjects.json`，每本书一个文件夹 `books/<文件夹名>/`，里面是 `book.json` 和 `cover.webp` 或 `cover.png`。文件夹名是书本不变的标识。
- 封面是 WebP 或 PNG，不超过 300 KB，宽高比 3:4；导入时检查，不缩图。
- 导入命令放在后端里，入口 `apps/api/src/rebuild.ts`，用 NestJS 应用上下文只启动数据库、对象存储和 `book` 模块的导入 service；任务命令是 `rebuild`。先校验全部文件，有错就什么都不改；再传封面，最后在一个事务里写数据库，按文件夹名更新或新增。可以重复运行。
- 书本数据按重建处理，在表结构迁移之后执行：测试环境由 CD 执行，开发机由 `task dev` 执行，测试对自己的固定数据执行。
- 现在 `content/` 里是 30 本示例书。

## 理由

- 文件在仓库里，改书本走 PR，有评审和历史，不用先做管理后台。
- JSON 不加依赖，用 Zod 校验，和接口约定的写法一样。
- 年级和学科都是数据，加减只改数据，不改代码。
- 不缩图就不用带原生二进制文件的图片库，封面由平台团队按规格做好。
- 导入命令和接口共用表定义、对象存储接入和配置校验，也受分层规则检查。
- 现在只有测试环境，示例书放在一个文件夹里最简单。

## 代价

- 改书本要提交、合并，等 CD 发布后才生效。
- 手写 JSON 时，长简介里的换行要转义，也不能写注释。
- 封面不合规格时导入会停下，要手动改图。
- 示例书和以后的正式书在同一个文件夹，建生产环境时要记得换掉。

## 何时重新考虑

- 书本多到手工维护文件吃力，或者要让编辑在网页上改内容。
- 建生产环境时。
- 教学和练习的内容格式确定时。
