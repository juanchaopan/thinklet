# 0044 练习判分和学习记录

## 背景

练习要判分：每道题的评分标准不一样，有的整题对错，有的按小题算百分比，有的按步骤；有的作答点有几种都算对的答案（比如给旋律配和弦）。练习可以重做，只保留最后一次的结果；孩子在每道讲题和练习上花的时间要进学习历史。

## 比较过的方案

- 判分在哪里：后端判分，浏览器拿不到答案；浏览器判分，再把分数报给后端。
- 评分标准写在哪里：题目文件里，流程文件写默认；写在代码里。
- 审计：照规则每次写一行；学习记录不写审计。

## 决定

- 答案和评分标准写在题目文件里：每个作答点的答案（可以有几种都算对的答案，或几组都算对的组合）、每个作答点几分，以及整题对错、按小题算百分比或按步骤。流程文件写这类题默认的判分方式，题目只写和默认不同的。
- 后端判分。判分代码是几种通用的规则，只读题目和流程的文件，不为某一道题写代码。发给浏览器的练习去掉答案和评分标准；孩子提交后，后端判分、存结果，再返回对错和正确答案。
- 每道练习只存最后一次作答：完成百分比、得分百分比和作答的时间，重做就覆盖。学习时间每看一次讲题或练习记一行。都按孩子编号和题目编号存，删除孩子时一起删掉。
- 提交练习、记一段学习时间、第一次打开一本书，都和别的改数据的动作一样写一行审计。

## 理由

- 孩子在浏览器里看不到答案，也报不了假分数。
- 评分标准跟着题目走，出题的人在一个地方写清楚；代码只有几种规则，加题不改代码。
- 审计规则没有例外，所有改数据的动作都查得到。

## 代价

- 提交后要等后端返回才看到对错。
- 审计表长得快一些。

## 何时重新考虑

- 要离线做题。
- 出现几种通用规则表达不了的评分方式。
