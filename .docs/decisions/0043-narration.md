# 0043 旁白录音

## 背景

讲题的老师有声音和字幕，孩子能上一句、下一句和调语速。不能用付费的、远程调用的 AI 模型。用户要求用 education 项目里的旁白引擎。

## 比较过的方案

- 声音：education 的引擎，edge-tts 的晓晓（`zh-CN-XiaoxiaoNeural`），照它的语速 −14%、音高 +5Hz；同一个声音的默认语速和音高。
- 录音放在哪里：和题目一起提交进仓库；Git LFS；不提交，发布时当场生成。
- 录音命令：新加 `task narrate`，用 uv 临时运行固定版本；在 Docker 容器里运行。

## 决定

- 用 edge-tts 的晓晓，默认语速和音高。
- `task narrate` 用 uv 的 `uvx` 临时运行 `edge-tts==7.3.1`（Python 3.12，第一次运行时由 uv 装好），只录台词或声音设置改过的句子。开发机录音时要装 uv，CI 和 CD 不用。
- MP3 和题目一起用普通 git 提交，放在题目文件夹的 `narration/` 里；同一个文件夹的清单记下每段录音的台词和声音设置的散列，内容检查据此核对录音和台词一致。
- 播放时浏览器用 `playbackRate` 变速，音高不变。

## 理由

- 和 education 用同一个声音，用户已经听过、认可。
- 默认语速最自然，孩子觉得快可以在播放时调慢。
- 录音提交进仓库，审题时听到的就是上线的；发布时不连微软的服务，它连不上也不影响发布。
- LFS 的免费额度很快会被 CI 的检出用完。

## 代价

- edge-tts 调用的是微软没有公开、没有开发者条款的接口；能不能用它生成发布给孩子的音频，要用户在上线生产环境前确认，否则换声音、重新录音。
- 仓库会大几十 MB。
- 录音要联网，开发机要多装 uv。

## 何时重新考虑

- 上线生产环境前，用户确认不能用 edge-tts。
- 出现许可明确、听起来同样好的本地声音。
