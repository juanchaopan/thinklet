# 0001 质量指标

## 背景

架构要先知道项目的规模、可用性、一致性、成本、维护能力，以及有没有性能、资源、安全、无障碍、兼容性方面的指标，后面的技术选择才有依据。简介里没有这些数字。

## 比较过的方案

| 方面 | 选项 |
|---|---|
| 规模 | 同时在线几百人以内；几千人；上万人或更多 |
| 可用性 | 99.5%；99.9%；没有要求 |
| 一致性 | 写入后立刻可见；可以晚几秒到几分钟 |
| 成本 | 每月 200 元以内；200–800 元；800 元以上 |
| 维护能力 | 一个人加 AI 代理；2–5 人的小团队；更大的团队 |
| 性能 | 页面和接口都要快；只要求页面加载快；没有 |
| 资源 | 限制前端包和服务内存；只限制前端包；没有 |
| 安全 | 按儿童信息的要求来；只做基本要求；没有 |
| 无障碍 | WCAG 2.1 AA；只管对比度和触控尺寸；没有 |
| 兼容性 | 主流浏览器的近两个大版本；另外专门测试微信内置浏览器；没有 |

## 决定

- 规模：同时在线几百人以内。
- 可用性：99.5%，允许偶尔停机。
- 一致性：写入后立刻可见。
- 成本：每月 200 元人民币以内。
- 维护能力：一个人加 AI 代理。
- 安全：按儿童信息的要求来。
- 无障碍：WCAG 2.1 AA。
- 兼容性：Chrome、Edge、Safari（含 iOS）、Firefox 的近两个大版本。
- 不设性能指标和资源指标。

## 理由

- 平台刚起步，按小规模来设计，花费和运维工作都最少。用户多了再通过 /change 扩容。
- 平台处理儿童的个人信息，要遵守《个人信息保护法》和《儿童个人信息网络保护规定》，所以安全按儿童信息的要求来。
- 无障碍的要求对低龄孩子也有帮助。
- 浏览器的范围和 Angular 官方支持的范围一致。

## 代价

- 没有性能指标，就不跑性能测试，慢的问题只能靠使用时发现。
- 99.5% 允许发布时停机，用户偶尔会碰到服务不可用。

## 何时重新考虑

- 同时在线人数接近上限，或者家长开始抱怨页面慢。
- 项目要商用，或者预算有变化。
- 维护的人变多了。
