# 0033 孩子登录

## 背景

#8 让孩子有自己的账号，由家长在家庭里建，孩子没有邮箱，不走 Authing。孩子用家庭码、账号和密码登录，或者扫家长给的一次性二维码，在自家设备上以后点头像就能登录；家长要能撤销记住的设备、删除孩子。孩子登录后不能用家长的权限。服务器无状态（决策 0030）。

## 比较过的方案

- 密码散列：Node 自带的 argon2id；`@node-rs/argon2`；Node 自带的 scrypt。
- 登录状态：和家长共用一个 cookie；孩子另用一个 cookie。
- 一次性链接和记住的设备：随机令牌、数据库存散列；签名令牌加作废名单。
- 同一个浏览器里家长已登录时：先让家长退出；允许同时登录。
- 防试密码：按账号计失败次数锁定；按 IP 限流；这次不做。
- 代码：新增 `child` 模块；放进 `family` 模块。

## 决定

- 孩子的账号和密码由本站管理，密码用 `node:crypto` 的 argon2id 加盐散列，参数写在散列字符串里。
- 孩子登录后，后端用签家长 JWT 的同一把 ES256 私钥签发孩子的 JWT，放在另一个 HttpOnly、Secure、SameSite=Lax 的 cookie 里。JWT 里写身份种类 `parent` 或 `child`；家长的接口只认家长 cookie 里的 `parent`，孩子的接口只认孩子 cookie 里的 `child`。
- 同一个浏览器里家长和孩子可以同时登录，各退各的。
- 孩子的每个请求都查一次孩子还在不在。
- 扫码登录链接和记住的设备都用 32 字节随机令牌，数据库只存 SHA-256，带过期时间和用掉的时间；撤销设备、删除孩子就删掉对应的行。
- 这次不限制试密码的次数。
- 后端新增 `child` 模块，调用 `auth` 导出的 service 签发 JWT，调用 `family` 导出的 service 查家庭码和成员关系。

## 理由

- Node 24.7 起自带 argon2，不加依赖也没有原生模块，argon2id 是 OWASP 首推的；按 OWASP 的最低参数一次约 43 毫秒。
- 家长把浏览器登录着留给孩子，孩子本来就能用家长的账号，孩子再登录自己的账号不多出风险；不让同时登录，只会让孩子登录比什么都没登录时更麻烦。
- 分开的 cookie 和身份种类，让只有孩子登录的浏览器打不开家长的接口，也防止把孩子的令牌当成家长的用。
- 无状态的签名做不到只能用一次和单台撤销，数据库只存散列，数据库泄漏也拿不到能用的令牌。
- 每次查孩子在不在，删掉孩子马上生效，和家庭成员每次查一样。
- `family` 已经管家长、家庭、成员和申请，孩子登录单独成模块，#9 的分派也要用孩子。

## 代价

- 同时登录的浏览器里，孩子能打开家长的页面，这和家长没退出时一样。
- 没有限制试密码的次数，知道家庭码和账号的人可以一直试；孩子的密码常常很简单。
- 孩子的 JWT 签发后，过期前没法单独作废，只靠每次查孩子在不在。
- argon2 每次登录要几十毫秒 CPU 和约 19 MiB 内存，要 Node 24.7 以上。
- 跨模块多一层调用。

## 何时重新考虑

- 有人试密码，或者要上生产环境。
- 要把孩子从某台正在用的设备上马上踢下线。
- 登录的 CPU 和内存成了问题。
