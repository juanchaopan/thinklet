# 0033 孩子登录

## 背景

#8 让孩子有自己的账号，由家长在家庭里建，孩子没有邮箱，不走 Authing。孩子用家庭码、账号和密码登录，或者扫家长给的一次性二维码，在自家设备上以后点头像就能登录；家长要能撤销记住的设备、删除孩子。孩子登录后不能用家长的权限。服务器无状态（决策 0030）。

## 比较过的方案

- 密码散列：Node 自带的 argon2id；`@node-rs/argon2`；Node 自带的 scrypt。
- 登录状态：和家长共用一个 cookie；孩子另用一个 cookie。
- 一次性链接和记住的设备：随机令牌、数据库存散列；签名令牌加作废名单。
- 同一个浏览器里家长已登录时：先让家长退出；允许同时登录。
- 防试密码：按账号计失败次数锁定；按来源 IP 限流；不做。#14 改成按来源限流（决策 0039）。
- 浏览器带来的设备令牌：格式对就沿用；库里有记录才沿用，没有就签发新的；再给所有 cookie 加 `__Host-` 前缀。
- 签发时间和 `sessions_valid_after` 的时钟：都取数据库的时间；比较时留几秒余量。
- 扫码登录链接放在哪里：数据库表；Redis。
- 过期的记住设备：孩子登录时删掉他过期的设备；不清理。
- 孩子的第一个密码：家长添加孩子时设初始密码；孩子第一次登录时自己设，用账号登录时不加期限；用账号登录设密码只在家长添加或重设后的 48 小时内能做。
- 代码：新增 `child` 模块；放进 `family` 模块。

## 决定

- 孩子的账号和密码由本站管理，密码用 `node:crypto` 的 argon2id 加盐散列，参数写在散列字符串里。
- 孩子登录后，后端用签家长 JWT 的同一把 ES256 私钥签发孩子的 JWT，放在另一个 HttpOnly、Secure、SameSite=Lax 的 cookie 里。JWT 里写身份种类 `parent` 或 `child`；家长的接口只认家长 cookie 里的 `parent`，孩子的接口只认孩子 cookie 里的 `child`。
- 同一个浏览器里家长和孩子可以同时登录，各退各的。
- 孩子的每个请求都查一次孩子还在不在。
- 扫码登录链接和记住的设备都用 32 字节随机令牌，只存 SHA-256。
- 扫码登录链接存在 Redis 里（决策 0039），10 分钟后自动消失；登录时用一条原子命令取出并删掉，只能用一次；同一个孩子生成新链接时旧的作废；家长查链接状态也读 Redis，状态留到链接过期。删除孩子时删掉 Redis 里他的链接。
- 记住的设备存在数据库里，带过期时间；撤销设备就删掉对应的行；孩子登录时，在同一个事务里删掉这个孩子已经过期的设备。
- 家长不给孩子设密码。孩子第一次登录时自己设密码；家长重设密码就是清掉密码，孩子下次登录时再设。扫码登录随时能设；用家庭码和账号登录时，只在家长添加孩子或重设密码后的 48 小时内能设，过了期限要扫码。
- 孩子用家庭码、账号和密码登录，以及扫码页输入密码，按来源 IP 限制失败次数（决策 0039）；不按孩子账号锁定。
- 孩子用密码或扫码登录并勾「在这台设备上记住我」时，每次都签发新的设备令牌：浏览器旧令牌下、同一个家庭的孩子还没过期的设备记录，在同一个事务里换到新令牌，别的家庭的不带过去。点头像登录沿用原来的令牌。cookie 的名字不加 `__Host-` 前缀。
- 签发孩子 JWT 的时间和重设密码时写的 `sessions_valid_after`，都取数据库的当前时间。
- 后端新增 `child` 模块，调用 `auth` 导出的 service 签发 JWT，调用 `family` 导出的 service 查家庭码和成员关系。

## 理由

- Node 24.7 起自带 argon2，不加依赖也没有原生模块，argon2id 是 OWASP 首推的；按 OWASP 的最低参数一次约 43 毫秒。
- 家长把浏览器登录着留给孩子，孩子本来就能用家长的账号，孩子再登录自己的账号不多出风险；不让同时登录，只会让孩子登录比什么都没登录时更麻烦。
- 分开的 cookie 和身份种类，让只有孩子登录的浏览器打不开家长的接口，也防止把孩子的令牌当成家长的用。
- 无状态的签名做不到只能用一次和单台撤销，只存散列，存储泄漏也拿不到能用的令牌。
- 扫码登录链接只活 10 分钟，放在 Redis 里到期自己消失，用掉就删，不会像数据库表那样越积越多；记住的设备要活很久、家长要看列表，留在数据库里，登录时顺手删掉过期的。
- 每次查孩子在不在，删掉孩子马上生效，和家庭成员每次查一样。
- `family` 已经管家长、家庭、成员和申请，孩子登录单独成模块，#9 的分派也要用孩子。
- 用户希望三种登录的第一次都由孩子自己设密码，不用家长转告密码。扫码链接只在家长屏幕上出现 10 分钟，家庭码却在邀请家长的链接里、账号常常好猜，所以用账号登录设第一个密码加一个 48 小时的期限，减少别人抢先设密码的机会。
- 按账号锁定会让别人故意输错就把孩子锁在外面；按来源限流挡住从一处大量试密码，也不怕被人拿来锁孩子。
- 每次输入密码或扫码登录都换新令牌、只带上同一个家庭的设备，预先写进浏览器的令牌（哪怕是攻击者自己合法拿到、库里有记录的）在孩子登录后就作废，变不成这个孩子的设备凭证；兄弟姐妹照样共用一台浏览器。加 `__Host-` 前缀要改所有 cookie 的名字，测试环境里所有人要重新登录。
- 两个时间都取自数据库这一个时钟，后端实例的时钟差多少都不会把刚登录的孩子误判成重设密码前的登录；留余量的做法会让重设密码前几秒签发的登录继续有效。

## 代价

- 同时登录的浏览器里，孩子能打开家长的页面，这和家长没退出时一样。
- 知道家庭码和账号的人，在家长添加孩子或重设密码后的 48 小时内能抢先替孩子设密码；家长发现后只能重设。
- 只按来源限流，换很多 IP 来试同一个孩子的人挡不住；孩子的密码常常很简单。
- cookie 不带 `__Host-` 前缀，同站的子域名还能往本站写 cookie。
- 签发孩子 JWT 时要多查一次数据库的时间。
- Redis 连不上时扫码登录用不了，家长也生成不了新链接；家庭码、账号和密码登录不受影响。
- 很久不登录的孩子，过期的设备会留到他下次登录。
- 一台浏览器上记住了不同家庭的孩子时，一个孩子用密码或扫码登录，别的家庭的孩子的头像就从这台浏览器上消失，下次要重新输密码；他们的旧设备记录用不了，到期后删掉，在那之前家长的设备列表里还看得到。
- 孩子的 JWT 签发后，过期前没法单独作废，只靠每次查孩子在不在。
- argon2 每次登录要几十毫秒 CPU 和约 19 MiB 内存，要 Node 24.7 以上。
- 跨模块多一层调用。

## 何时重新考虑

- 有人试密码，或者要上生产环境。
- 要把孩子从某台正在用的设备上马上踢下线。
- 登录的 CPU 和内存成了问题。
