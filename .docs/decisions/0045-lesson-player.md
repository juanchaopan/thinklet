# 0045 讲题和练习的播放器

## 背景

孩子看讲题、做练习，家长从书本页预览，用的是同一套播放器和组件。组件以后会越来越多，加组件要有固定的做法。截图对比要能发现组件和播放器的变化，又不能让基准图多到改不动。

一道题要用的东西不少：组件的代码、钢琴采样、旁白录音、图片和字体。在用户的手机上试过，采样在第一次点音符或播放时才开始下载，前几个音挤在一起，还有延迟。手机又只在用户的操作里才能开始出声。

## 比较过的方案

- 播放器和组件放在哪里：`apps/web/src/app/shared/lesson/`，不调接口；单独的 workspace 包 `packages/lesson`。
- 截图对比覆盖到哪一层：组件、播放器和页面，每道题不截图；每道题的每一幕也截图。
- 题目的东西什么时候下载：打开题目时先显示加载页，全部下载好再开始；用到时再下载。

## 决定

- 播放器、每个组件一个文件夹、组件编号到代码的对照表，都放在 `apps/web/src/app/shared/lesson/`。它们只接收数据、发出事件，不调接口；`shared/lesson` 可以用 `shared/ui`，反过来不行。
- 孩子的书和家长预览各是 `features` 里的页面，负责取数据和提交。
- 加组件：加一个文件夹，在 `packages/contracts` 里加它参数的 schema，在对照表里登记。
- 组件测试截图对比组件的各种状态、播放器和页面，用测试自己的固定题目，三种屏幕各一张；书里的每道题不截图，由内容检查和用户亲自审题来保证。
- 讲题和练习打开时，播放器先显示加载页，显示进度，把这道题要用的东西全部下载好、准备好：题目文件、用到的组件的代码、钢琴采样（解码成可以直接播放的声音）、旁白录音、图片和字体。全部好了以后出现「开始」按钮，孩子点了才开始。这一下也是手机允许出声的那次操作，所以第一句旁白和第一个音都能准时出来。
- 加载失败时加载页说明没准备好，给一个「再试一次」。
- 组件不自己下载东西，也不在第一次用到时才加载；它要的资源都由播放器在加载页里准备好再交给它。

## 理由

- 只有一个应用用它，单独成包要多维护构建、测试和类型检查。
- 不调接口，孩子做题和家长预览就能共用，组件测试也不用替换接口。
- 每道题都截图会有上千张基准图，改一个组件就要全部重新生成。
- 一道题的东西不大（采样约 0.5 MB，加上几句旁白和几张图），一次下载完，等几秒换来讲题里每个声音都准时，比讲到一半卡住好。
- 旁白要自动播放，手机上必须先有一次用户的操作；「开始」按钮正好是这一次，不用再在讲题里另找时机解锁声音。

## 代价

- 题目内容的显示问题，截图对比发现不了，要靠审题。
- 每道题开始前多一页、多点一下；网速慢时要等。采样由浏览器缓存，第二道题起快得多。

## 何时重新考虑

- 出现第二个要用播放器的应用。
- 发现审题经常漏掉题目内容的显示问题。
- 一道题要下载的东西大到加载页要等很久，比如带视频的题。
