# 0031 家庭和家长成员

## 背景

家长和家庭是两个概念。一个家庭可以有几位家长，各用各的账号登录，共用同一个家庭；一位家长也可以属于几个家庭，比如分开住的父母、帮几个子女带孩子的祖父母。家庭有家庭码，孩子登录要用它（#8）。

## 比较过的方案

- 一位家长属于几个家庭：只属于一个；可以属于多个。
- 几位家长的权限：所有家长一样；一位管理员加普通家长。
- 怎么加入：管理员发的一次性邀请，拿到就直接加入；输入家庭码申请加入，管理员同意。
- 申请加入用几个码：和孩子登录共用家庭码；另设一个只给家长的邀请码。
- 接口怎么知道是哪个家庭：家庭编号放在接口路径里；当前家庭放在 JWT 里。

## 决定

- 家长和家庭是多对多的成员关系，一位家长可以属于多个家庭。
- 每个家庭恰好一位管理员：创建家庭的人是管理员，可以把管理员交给另一位家长。家庭设置（名称、时区、刷新家庭码）和成员管理（处理申请、移除家长）只有管理员能做；其他家长只能看。管理员以外的家长可以自己离开，管理员要先交出管理员才能离开。
- 加入家庭：输入家庭码，或者打开带家庭码的链接，发出加入申请，管理员同意后成为家庭的家长。家庭码长期有效，管理员刷新后旧码作废，用旧码发出、还没处理的申请也一起作废。
- 孩子登录和家长申请加入共用同一个家庭码。孩子记住登录的设备用设备自己的凭证，不用家庭码，所以刷新家庭码不影响它们（#8 按这一点设计“记住我”）。
- 一个家庭里的接口都在 `/api/families/{familyId}/...` 下。每个请求先查这位家长是不是这个家庭的成员，要管理员的再查角色；不是成员的一律当作找不到。
- JWT 里只放家长编号，不放家庭和角色。前端在浏览器里记住上次用的家庭，登录后进入它。
- 具体的表、字段和约束在设计文档里定，数据库要保证每个家庭恰好一位管理员、家庭码全平台不重复。

## 理由

- 一开始就按多对多建，以后不用再迁一次数据。
- 一位管理员，权限规则简单，申请和移除也有人负责。
- 加入要管理员同意，就算知道家庭码的孩子或外人发了申请，管理员不同意也进不来，所以不用再多一个码让家长分辨。
- 家庭编号放在路径里，切换家庭不用重新签发 JWT，两个标签页可以各看一个家庭；被移出家庭或交出管理员后，下一个请求就生效。

## 代价

- 一个家庭里的每个接口都要多查一次成员关系。
- 知道家庭码的人都能发申请，管理员可能收到陌生人的申请，要看清申请人再处理。
- 为了让某个申请作废而刷新家庭码时，孩子手动登录也要用新码。
- 管理员不在了（比如不再登录），家庭就没人能改设置、处理申请。

## 何时重新考虑

- 一个家庭要有几位管理员，或者要更细的权限。
- 要删除家庭，或者处理管理员不在的家庭。
- 陌生人的加入申请多到成为负担。
