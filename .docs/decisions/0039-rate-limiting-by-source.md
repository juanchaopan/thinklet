# 0039 按来源限流

## 背景

孩子用家庭码、账号和密码登录，以及扫码页输入密码，每次尝试要做一次约 43 毫秒的 argon2，孩子的密码又常常很简单（决策 0033）；查家庭码的接口没有频率限制，登录的家长可以枚举家庭码。后端在测试环境里是 Vercel 函数，每个请求都可能落在不同的实例上，计数要放在实例之外。孩子的扫码登录链接只活 10 分钟、只能用一次，用掉和过期的却一直留在数据库表里。生产环境放在中国大陆的云上，还没有建。

## 比较过的方案

- 按什么限：按孩子账号连续失败锁定；按来源 IP 限流；两种都做。
- 计什么：每次尝试都算；只算失败，孩子登录分按来源加孩子和按来源合计两层。
- 计数放在哪里：PostgreSQL 里的计数表；Vercel 防火墙的限流规则；一个 Redis 类的服务。
- Redis 客户端：node-redis（`redis`）；ioredis。
- 键里放什么：来源 IP 的 HMAC 值；IP 原文。
- 开发机和测试里的 Redis：`valkey/valkey` 镜像；`redis` 官方镜像。
- 健康检查查不查 Redis。
- Redis 连不上时：照常放行并记错误日志；拒绝请求。
- 测试环境的库怎么建：代理用 Upstash 的开发者 API 建；用户在网站上建。

## 决定

- 孩子用家庭码、账号和密码登录，扫码页输入密码，家长查家庭码，这三个接口按来源 IP 限制一个时间窗口里的失败次数，成功的不算。孩子登录的两个接口合起来计，分两层：同一个来源对同一个孩子，和同一个来源对所有孩子合计；查家庭码只算查不到的。次数和窗口由设计定。不按孩子账号锁定。
- 计数放在 Redis，后端用 node-redis 走标准 Redis 协议，连接地址是密钥 `REDIS_URL`。测试环境用 Upstash 免费档，新加坡区，由代理用 Upstash 的开发者 API 建，连接地址直接写进 GitHub，不显示。
- 键里是来源 IP 的 HMAC-SHA256 值，子密钥由 `CHILD_DATA_KEY` 用 HKDF 推出；每个键只活一个时间窗口，到期自动消失。Redis 里的计数不迁移。
- 来源 IP 只认前端代理写的请求头；是哪一个头，由 scaffold 步骤在测试环境上核对后写进架构。
- Redis 连不上时照常放行，记一条错误日志。
- Redis 也放孩子的扫码登录链接（决策 0033）；扫码登录离不开它，所以健康检查也向 Redis 发 `PING`，不通就返回 503。
- 开发机和测试里用 Valkey 容器（`valkey/valkey`）：开发时用 Docker Compose 起，测试时用 Testcontainers 临时起。

## 理由

- 按账号锁定，别人故意输错就能把孩子锁在外面；按来源限流挡住从一处大量尝试，用户决定只按来源。
- 学校和小区里很多孩子共用一个出口 IP，一个班一起登录时每次都算会马上碰到上限；只算失败、再按孩子分开计，同一个出口后面的孩子互不影响，合计的那一层挡住从一处批量试很多账号。
- Redis 的计数自带过期，原子地加一，正适合限流；Vercel 防火墙的规则只管测试环境，生产环境要重做，本机和 CI 的测试也测不到。
- Upstash 免费档每月 50 万条命令、256 MB，每次尝试约 2 条命令，测试环境每月 0 元；代码只用标准协议，生产环境换成国内云的 Redis（阿里云、腾讯云 256 MB 新用户首年约 72–80 元）只改地址。
- node-redis 是 Redis 官方维护的客户端，自带类型；ioredis 已经进入维护模式。
- 存 HMAC 值，Redis 里看不到 IP 这种个人信息；用已有的主密钥推出子密钥，不加新密钥，换主密钥时计数归零也没有影响。
- 限流只是一层保护，Redis 出故障时放行，孩子照常能用家庭码、账号和密码登录。
- 扫码登录要用 Redis，健康检查查它，部署后的冒烟测试就能发现 `REDIS_URL` 配错或 Upstash 连不上。
- Valkey 是 Linux 基金会维护的 Redis 分支，BSD-3-Clause，用到的命令和 Redis 一致；Redis 8 的许可证是 AGPLv3、RSALv2、SSPL 三选一。
- 和 Neon 一样由代理用命令建，重建时照着做就行；Upstash 的官方命令行已经不维护，所以用它的开发者 API。

## 代价

- 多一个组件、一个外部服务和一个密钥，开发机和测试多起一个容器。
- 换很多 IP 来试同一个孩子的人挡不住；同一个出口 IP 后面有人大量试错时，合计的那一层会把这个出口后面的孩子一起拦住。
- Redis 出故障期间没有限流保护，扫码登录也用不了，健康检查返回 503。
- 来源 IP 取决于前端代理写的请求头，换托管方式时要重新核对；核对不出可信的头时要回到 architect 步骤。
- 用户要在 Upstash 网站上注册并生成 API 密钥。
- 开发和测试用的 Valkey 和测试环境的 Upstash 不是同一个产品，个别命令的行为可能不同。

## 何时重新考虑

- 有人换着 IP 试同一个孩子的密码。
- 很多家庭共用一个出口 IP，经常被误限。
- 建生产环境，选国内云的 Redis。
- 有别的东西要放进 Redis，或者 Redis 的故障开始影响可用性。
