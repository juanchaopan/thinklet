# 0024 风险规则

## 背景

每个 PR 按改到的文件分成低、中、高三级风险。中、高风险的 PR 合并前要有人批准。

## 比较过的方案

- 用常见的起点，改成本项目的路径。
- 另外把 `packages/contracts/**` 也算作高风险。
- 低风险里去掉 `**/*.md` 和 `**/*.txt`。

## 决定

用常见的起点，改成本项目的路径，写在仓库根目录的 `risk-rules.yml` 里。具体路径见 `architecture.md` 的“风险规则”一节。

- 高风险：流程和检查本身、截图基准图、登录认证、迁移脚本、环境文件、部署配置、`apps/api/src/infrastructure/**`。
- 低风险：`.docs/**`、`**/*.md`、`**/*.txt`、`LICENSE`。
- 同时属于两边的，按高风险算。
- 发版 PR 一律是高风险。

## 理由

- 放宽检查、改基准图、改 CI 都必须有人看过。
- 接口约定包几乎每个功能都会改，算成高风险会让大部分 PR 都变成高风险。

## 代价

- 改界面的 PR 一般会更新截图基准图，所以都是高风险。

## 何时重新考虑

- 做家长和孩子数据的 issue，要把那些模块的路径加进高风险。
