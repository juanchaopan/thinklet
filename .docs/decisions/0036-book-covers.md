# 0036 封面图的存储和读取

## 背景

#9 要把封面图传到对象存储，再在书库里显示。前端 CSP 的 `img-src` 只允许本站。测试环境和生产环境的对象存储不是同一家（决策 0006）。

## 比较过的方案

- 读取：后端转发；预签名的存储直链；公开读的存储桶。
- 取封面要不要登录：要家长或孩子登录；不用登录。
- 存储里的命名：和仓库一样按书本分文件夹，换封面就覆盖；按图片内容的散列命名。
- 缓存：地址带图片的散列，长期缓存；地址固定，不长期缓存。

## 决定

- 对象存储里按书本分文件夹：`books/<书本编号>/cover.webp` 或 `.png`，换封面就覆盖；内容没变的不重传。
- 浏览器经过后端的接口取封面，要家长或孩子登录；后端从对象存储读出原样返回。
- 取封面的地址带上书本表里的封面散列；响应只让浏览器自己长期缓存。

## 理由

- 走本站的地址，前端 CSP 不用放开存储的域名，也不依赖哪家存储的公开地址或预签名的细节，生产环境换存储只改配置。
- 存储里的结构和仓库一样，好找，也好对照。
- 地址带散列：换了图马上能看到新的，没换的图长期缓存，不重复下载。

## 代价

- 每张封面第一次被取时要经过一次 Vercel 函数，占函数调用和流量的额度；几十本书用不完。
- 要登录才能取，响应不能放在 CDN 上共用。
- 覆盖封面的那一刻，拿着旧地址的请求会取到新图。

## 何时重新考虑

- 图片多、流量大，后端转发成为负担，需要 CDN 或存储直链时。
- 选定生产环境的云服务商时。
